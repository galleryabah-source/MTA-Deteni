# P10.14 — Database Integration Verification Package

## Status

PREPARED — executable verification remains blocked while `MIGRATION_FREEZE=TRUE`.

## Objective

Turn the P10.13 execution gate into a deterministic verification package without executing DDL or connecting to a production database.

## Verification layers

1. Migration artifact integrity: path, version, checksum and review-only marker must match the approved package.
2. Schema contract: table, lifecycle constraints, indexes and RLS enabled state must match P10.12.
3. Privilege contract: `anon`, `public` and unapproved `authenticated` access remain denied.
4. Identity/scope contract: actor identity and scope are authoritative, server-established and fail-closed.
5. Repository contract: parameterized insert plus atomic consume/revoke; exactly one affected row is required for terminal transitions.
6. Transaction contract: grant creation, audit and outbox occur on the same transaction client; provider/network work occurs only after commit.
7. Concurrency contract: independent PostgreSQL sessions demonstrate one successful consume and one or more zero-row losers.
8. Rollback contract: rollback preserves audit/retention evidence and does not improvise destructive deletion.

## Evidence format

Evidence must contain only operational metadata and synthetic identifiers: test ID, timestamp, database identity, transaction/session identifier where safe, SQL operation class, affected-row count, final lifecycle state, audit event ID, outbox event ID and pass/fail result. Never store detainee names, health information, document contents, credentials, access tokens or provider secrets.

## Hard-stop behavior

The verification runner MUST refuse execution when `MIGRATION_FREEZE` is true, the target identity is missing or mismatched, the approved artifact checksum is unavailable, identity/scope mapping is ambiguous, or required evidence cannot be persisted.

A test result of `SKIPPED_BY_SAFETY_GATE` is not a PASS. Certification remains blocked until real PostgreSQL evidence is produced after authorized execution.

## No implicit authority

The package does not authorize migration, RLS deployment, privilege changes, production access or release. Authorization remains external to the test package and must be explicitly recorded before execution.
