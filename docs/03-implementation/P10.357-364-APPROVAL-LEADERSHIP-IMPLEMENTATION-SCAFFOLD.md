## Components

```text
Approval request
 → server-side authorization + scope
 → SoD / conflict check
 → state/version validation
 → decision transaction
 → audit/outbox
 → cache invalidation where policy changes apply
```

Required operations: submitForApproval, approve, reject, revokeDecision, getApprovalHistory, createLeadershipDirection, acknowledgeDirection, recordDirectionResponse, closeDirection.

Approval must never operate on stale/revoked state. Self-approval and incompatible-role conflicts fail closed. Critical policy/RBAC changes follow re-authentication and second-approval controls already established by the security contract.

Leadership directions (PETUNJUK/ARAHAN/REKOMENDASI/DISPOSISI) are auditable workflow objects with acknowledgement, response/follow-up, and closure. They do not silently rewrite operational facts.

## Test gate

Synthetic tests cover valid approval, denial, wrong role, wrong scope, stale object, revoke race, self-approval conflict, critical second approval, leadership lifecycle, cache refresh, duplicate replay, and audit rollback.

No migration or live database mutation is authorized by this scaffold.
