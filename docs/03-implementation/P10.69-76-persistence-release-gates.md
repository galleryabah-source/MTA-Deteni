# MTA DETENI — P10.69–P10.76 Persistence & Release Gates

## Purpose

These checkpoints harden the temporary-exit vertical slice before any database migration or provider activation. They define contracts and negative tests only; they do not execute schema changes.

## Gates

- **P10.69 — Persistence adapter contract:** transaction, idempotency, audit, outbox, and scope enforcement are mandatory capabilities.
- **P10.70 — Integrity capabilities:** idempotency, audit append, and outbox append cannot be omitted from the persistence boundary.
- **P10.71 — Provider isolation:** WhatsApp/external providers are fail-closed until the persistence transaction is committed.
- **P10.72 — Migration freeze:** schema-changing operations are blocked while `MIGRATION_FREEZE=true`.
- **P10.73 — Scope enforcement:** persistence adapters must expose an authoritative scope check; client-supplied scope is not sufficient authority.
- **P10.74 — Provider separation:** provider/network calls are not part of the persistence transaction contract and must be dispatched post-commit.
- **P10.75 — Synthetic release safety:** production data, repository secrets, and AI runtime activation remain prohibited in the test gate.
- **P10.76 — Pre-database release gate:** persistence contract validation must succeed before database execution is considered eligible.

## Evidence boundary

P10.69–P10.76 are **readiness contracts**, not database certification. No migration is executed by these checkpoints. Certification remains blocked until controlled database execution, RLS verification, runtime integration, CI evidence transport, rollback evidence, and governance approval are independently demonstrated.

## Required invariants

1. Critical mutations occur inside a transaction boundary.
2. Audit and outbox records are part of the same critical transaction.
3. Idempotency is evaluated before duplicate mutation can occur.
4. Provider calls occur only after commit.
5. Scope is server-authoritative.
6. Migration freeze is fail-closed.
7. AI remains OFF.
8. Test fixtures remain synthetic.
9. `main` is not modified by implementation work.
