# MTA DETENI — P9.8 Executable Implementation Status

## Scope

The branch contains a dependency-free executable outbox/idempotency foundation plus a transactional command-boundary test kernel aligned to the P9.8 contract. A production PostgreSQL critical-transaction adapter boundary is now present and deliberately contains no schema-specific SQL or migration logic.

## Implemented invariants

- immutable event identity via `eventId`;
- event contract validation;
- correlation metadata requirement;
- `PENDING → PROCESSING → SUCCEEDED` lifecycle;
- retry lifecycle;
- dead-letter lifecycle;
- lease owner and lease expiry;
- stale-lease recovery;
- duplicate event identity rejection;
- deterministic request fingerprinting;
- same-key replay;
- same-key/different-payload conflict;
- worker lease ownership on completion/retry/dead-letter;
- AI/provider independence at kernel level;
- atomic command model: domain mutation + audit + outbox;
- rollback on domain, audit, outbox, or commit failure in the test kernel;
- production adapter requires domain mutation, audit append and outbox enqueue to receive the same PostgreSQL `PoolClient` transaction context;
- no external-provider call is modeled inside the critical transaction.

## Executable evidence

Local Node built-in test execution previously passed **12/12** tests across the transactional-boundary and private-storage slices used for this checkpoint. The P9.8 transaction-boundary suite covers atomic commit, rollback on outbox/audit failure, idempotent replay, key-reuse conflict, and provider-call isolation.

## Production adapter boundary

`src/kernel/critical-transaction.ts` provides `executeCriticalTransaction()`. It delegates transaction ownership to the existing PostgreSQL `Database.transaction()` wrapper and executes domain mutation, audit append, and outbox enqueue sequentially on the same `PoolClient`. It does not define tables, indexes, migrations, provider calls, or credentials.

## Deliberate boundary

This implementation does **not** claim transactional database atomicity until connected to an approved schema and exercised against PostgreSQL with failure injection and concurrency tests. No migration is performed here.

GitHub Actions is configured to execute the kernel suite, but the latest P9 Kernel run failed before exposing actionable runner steps/logs; a rerun was attempted and the connector still exposes no usable runner evidence. CI is therefore not represented as PASS.
