# MTA DETENI — P13.2201–P13.2440 Local Continuity

## Purpose
Establish the contract foundation for running MTA DETENI through a local PC/server on the same Wi-Fi while preserving continuity for tablet and smartphone clients during intermittent internet connectivity.

## Checkpoints
- P13.2201–2240 — local-device runtime packaging contract.
- P13.2241–2280 — fail-closed synchronization queue integrity.
- P13.2281–2320 — backup/restore evidence contract.
- P13.2321–2360 — synthetic multi-device acceptance.
- P13.2361–2400 — continuity release gate.

## Architectural Boundary
The local runtime is a continuity mechanism, not a second source of truth. The repository remains synthetic-only. Offline/local operation does not authorize mutation by itself. Synchronization is allowed to commit only after queue completion and controlled validation. Conflicts remain blocked.

## Device Model
The contract explicitly covers PC, tablet and smartphone classes. A PC can host the local application runtime while client devices connect over the local network. Internet loss must not silently convert a client into an authority boundary.

## Backup / Restore
Backup evidence is represented as an auditable contract. Restore is considered verified only when an explicit VERIFIED result exists. NOT_RUN and FAILED remain non-promotable states.

## Multi-device Acceptance
Acceptance is synthetic and requires the declared device classes. It does not execute against production data and does not imply production authorization.

## Governance
Migration Freeze remains TRUE. AI remains OFF. Production authorization remains FALSE. No schema migration or live PostgreSQL execution is introduced by this checkpoint.

## Gate
P13.2440 is contract-ready only. Execution certification remains pending until observable CI/local execution evidence is available.
