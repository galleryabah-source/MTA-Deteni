# P9.2 — MTA DETENI Edge Runtime Configuration Contract v1.0

## Status
- Source implementation: included in the P9.2 runtime configuration hardening PR.
- Runtime environment values: not changed by this work.
- Production write activation: remains OFF unless both explicit controls are satisfied.
- Production deployment: not authorized by this document.

## Required server-side configuration

| Variable | Requirement | Handling |
|---|---|---|
| `SUPABASE_URL` | Required | Valid HTTPS URL; loopback HTTP only when environment is LOCAL, DEVELOPMENT, or TEST |
| `SUPABASE_ANON_KEY` | Required | Server runtime value; never logged |
| `SUPABASE_SERVICE_ROLE_KEY` | Required | Server-only; never exposed to browser or logs |
| `MTA_ENVIRONMENT` | Optional but recommended | `PRODUCTION`, `STAGING`, `DEVELOPMENT`, `TEST`, `LOCAL`, or `UNSPECIFIED` |
| `MTA_PRODUCTION_WRITES_ENABLED` | Optional; defaults OFF | Must be exactly `true` or `false` |

## Production write gate

The effective value is:

```text
productionWritesEnabled =
  (MTA_PRODUCTION_WRITES_ENABLED == "true")
  AND
  (MTA_ENVIRONMENT == "PRODUCTION")
```

A true flag in STAGING, DEVELOPMENT, TEST, LOCAL, or UNSPECIFIED does not enable production writes. Invalid flag/environment values fail configuration loading.

## Runtime behavior

1. Both `mta-api` and `mta-login` load the shared configuration once at module initialization.
2. Missing required values or malformed URL/environment values fail fast.
3. Validation errors expose variable names only; secret values are never included.
4. Supabase URL credentials, query strings, fragments, and non-root paths are rejected.
5. Anon and service-role keys must be distinct; loopback HTTP is rejected for STAGING, PRODUCTION, and UNSPECIFIED.
6. The service-role key is accessed only by server-side Edge Function code.
7. Configuration values are not written into Git, browser storage, audit metadata, or application logs.

## Verification contract

- Valid production configuration parses and freezes.
- Missing required keys fail fast without echoing values.
- Unsafe URL schemes and URL components are rejected.
- Loopback HTTP is accepted only for local development.
- Production writes require both the explicit write flag and PRODUCTION environment.
- Edge Functions contain no ad hoc environment reads outside the shared loader.

## Change-control boundary

This work changes application source and tests only. It does not change Supabase secrets, Cloudflare variables, database schema, migrations, production data, or deployment configuration. Production remains NO-GO until the remaining audit findings and runtime gates are closed.
