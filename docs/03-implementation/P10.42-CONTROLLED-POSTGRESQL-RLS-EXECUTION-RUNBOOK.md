# P10.42 — Controlled PostgreSQL / RLS Execution Runbook

**Execution state:** PREPARED ONLY. This document is intentionally non-executable.

## Gate 0 — Safety

STOP unless `APP_ENV` is an explicitly approved target environment, `AI_ENABLED=false` for migration work, the governance decision is present, and Migration Freeze has been explicitly lifted by the authorized process. The repository must never contain credentials.

## Gate 1 — Immutable inputs

Record SHA-256 for the approved migration bundle, RLS policy bundle, application release commit, and rollback package. Do not edit these inputs during the change window.

## Gate 2 — Target verification

Independently verify database host/project identity, database name, role, environment marker, connection security, and current schema inventory. Abort on mismatch.

## Gate 3 — Backup / restore evidence

Create or verify a recoverable backup according to the approved operational platform. Record backup identifier, timestamp, retention, restore-test result, and responsible operator. Do not claim recoverability merely because a backup command returned success.

## Gate 4 — Migration

Apply only the approved migration bundle. Capture statement-level output and post-migration schema inventory. Any unexpected DDL, extension, privilege, owner, trigger, policy, or index change is a hard stop.

## Gate 5 — RLS

Verify RLS is enabled where required, no unintended public/anonymous grants exist, authenticated access is bound to authoritative actor identity and scope, and negative tests prove cross-actor and cross-scope denial. Super Admin administrative authority must not create operational bypass.

## Gate 6 — Concurrency / transaction

Run controlled synthetic tests for grant consume/revoke races, expiry, rollback, idempotency, audit atomicity, and outbox commit ordering against the real PostgreSQL target. Preserve raw evidence.

## Gate 7 — Application runtime

Only after database verification, validate deployed authentication, authorization, document lifecycle, persistent artifact grant, audit, outbox, storage and provider boundaries. External provider calls occur post-commit.

## Gate 8 — Abort / rollback

Rollback is a governed operation, not an improvised reverse migration. Stop writes/workers, preserve audit and regulated evidence, invoke the approved rollback plan, restore/repair only under authorization, then re-run integrity checks.

## Completion criteria

The change is complete only when all required evidence artifacts are independently observable, hashes match, negative security tests pass, monitoring is active, and an authorized release owner records the disposition. Otherwise status remains BLOCKED.
