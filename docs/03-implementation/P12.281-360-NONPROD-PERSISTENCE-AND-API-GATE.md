# P12.281–360 — Non-Production Persistence, Outbox Projection & API Boundary Gate

## Objective

Advance the MTA DETENI application boundary without opening production access or schema migration. This checkpoint makes the previously defined persistence, idempotency, outbox and API contracts concrete in a controlled in-memory/non-production form.

## Delivered

### P12.281–320 — Controlled persistence adapters

- `InMemoryGovernedTransaction` provides a non-production unit-of-work boundary and stages audit/outbox side effects before commit.
- `InMemoryPersistentIdempotency` implements the approved persistent-idempotency contract with key, fingerprint, actor, correlation and aggregate identity checks.
- Failed work does not commit staged audit/outbox effects.
- This adapter is a safety/test implementation, not a production PostgreSQL transaction adapter.

### P12.321–344 — Outbox-driven read-model projection

- `OutboxReadModelProjector` consumes committed outbox messages.
- Projection is explicitly downstream/event-driven and therefore rebuildable/eventually consistent.
- The command mutation path must not treat a projection failure as permission to mutate domain state a second time.

### P12.345–360 — Controlled API command boundary

- Requests require command identity, permission, fingerprint and actor/correlation/idempotency identity.
- Invalid identity is rejected before the command surface is executed.
- Authorization and idempotency conflicts are mapped to controlled error classes.
- No direct persistence, SQL, WhatsApp, OCR or AI path is exposed by this boundary.

## Regression coverage

`test/p12-281-360-integration-boundary.test.ts` covers:

1. successful transaction-side-effect commit;
2. persistent idempotency acquire/replay/conflict;
3. outbox-to-read-model projection;
4. API identity preflight rejection.

## Important boundary

The in-memory transaction is deliberately not described as production-grade atomic PostgreSQL execution. A future concrete PostgreSQL adapter must bind domain mutation, audit, outbox and idempotency state to one actual database transaction and provide observable rollback/commit telemetry before execution certification.
