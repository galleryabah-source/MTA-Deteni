# P10.25 — Controlled Runtime Boundary Preparation

Status: PREPARED — synthetic contract only.

HTTP request → request/correlation identity → authentication → authorization → input validation → domain command → critical transaction → audit → outbox → response.

Security invariants:
- authentication establishes identity; authorization establishes authority;
- authorization is deny-by-default and evaluates permission, scope, duty, resource, state, classification, policy and SoD;
- Super Admin administrative authority never becomes operational authority implicitly;
- sensitive resource lookup cannot become an IDOR/existence-disclosure channel;
- critical mutation is transactional and idempotent;
- mandatory audit/outbox belong to the critical transaction boundary;
- provider/network work occurs only after commit through outbox processing;
- secrets are never exposed to client bundles or normal logs;
- AI remains OFF and is not a critical dependency.

No production DB, migration, real detainee data, provider or credentials are activated.
