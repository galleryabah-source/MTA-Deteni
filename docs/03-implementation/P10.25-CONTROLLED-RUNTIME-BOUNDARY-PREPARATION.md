# P10.25 — Controlled Runtime Boundary Preparation

Status: PREPARED — synthetic contract only.

## Purpose

Define the runtime enforcement boundary before production infrastructure is activated.

Request flow:

HTTP request → request/correlation identity → authentication → authorization → input validation → domain command → critical transaction → audit → outbox → response.

## Security invariants

- Authentication establishes identity; authorization establishes authority.
- Authorization is deny-by-default and evaluates permission, scope, duty, resource, state, classification, policy and SoD.
- Super Admin administrative authority never becomes operational authority implicitly.
- Resource lookup must not become an IDOR or existence-disclosure channel.
- Critical mutation is transactional and idempotent.
- Mandatory audit and outbox belong to the critical transaction boundary.
- Provider/network work occurs only after commit through outbox processing.
- Authentication/session secrets are never exposed to client bundles or normal logs.
- AI remains OFF and is not a critical dependency.

## Enforcement matrix

| Boundary | Required behavior | Failure mode |
|---|---|---|
| Missing authentication | reject before protected resource resolution | AUTH_REQUIRED |
| Invalid/expired/revoked session | reject | AUTH_REQUIRED |
| Missing permission | reject | PERMISSION_DENIED |
| Wrong scope | reject | SCOPE_DENIED |
| Missing/inactive duty | reject | DUTY_REQUIRED / DUTY_INACTIVE |
| Classification insufficient | reject | RESOURCE_CLASSIFICATION_DENIED |
| Invalid lifecycle state | reject | INVALID_STATE |
| SoD violation | reject | SEGREGATION_OF_DUTIES |
| Super Admin operational bypass | reject | SUPER_ADMIN_OPERATIONAL_BYPASS |
| Duplicate idempotency key/equivalent request | replay safely | REPLAY |
| Duplicate key/conflicting request | reject | IDEMPOTENCY_KEY_REUSE |
| Audit/outbox transaction failure | rollback critical mutation | transaction failure |
| Provider failure after commit | retry/dead-letter via outbox | no rollback of committed domain state |

## Runtime endpoint classes

1. Read endpoints: authentication → authorization → scope/classification → query.
2. Non-critical writes: authentication → authorization → validation → domain service → audit.
3. Critical state transitions: authentication → authorization → validation → domain transaction → audit → outbox → commit.
4. Artifact downloads: authentication → authorization → persistent grant validation → atomic single-use consume → private storage read.

## Explicit non-goals

No production database connection, schema migration, real detainee data, production provider, AI activation, or production credentials are introduced by P10.25.
