# MTA DETENI — P13.361–P13.560 Controlled Application Surface

## Objective

Extend the existing governance chain into a controlled application surface without introducing production access, schema migration, live PostgreSQL execution, AI, or real detainee data.

## P13.361–420 — Application Orchestration

`ControlledApplicationOrchestrator` binds authorization, idempotency and transaction boundaries around a domain command. The command retains the canonical `DomainCommand` shape; command identity, permission, aggregate identity and fingerprint remain orchestration metadata.

Order of protection:

1. Validate orchestration identity and actor correlation context.
2. Authorize the requested permission against the aggregate resource.
3. Attempt safe replay.
4. Acquire idempotency key/fingerprint.
5. Execute domain handler inside the transaction boundary.
6. Complete the idempotency record with the resulting domain result.

This is a controlled contract, not a claim of atomic production persistence. Existing persistence limitations remain governed by the Migration Freeze.

## P13.421–480 — Operator Dashboard Read Model

The dashboard is composed only from derived/read-model inputs. It exposes detainee operational status, placement, QR status, headcount/reconciliation, pending temporary exits, pending approvals and operational alerts.

Role access follows the existing role matrix. The composer does not grant new authority; it only enforces the existing `dashboard.read` capability.

## P13.481–520 — Reporting Preview

The report preview validates the existing Regu Jaga report contract before any artifact generation. It preserves `reportId` and `sourceSnapshotId`, exposes validation errors and summarizes section/row counts.

Preview readiness is therefore a gate before report artifact generation, not an alternate write path.

## P13.521–560 — Synthetic Acceptance Catalog

Ten synthetic scenarios cover authorized dashboard access, denied access boundary, correlation integrity, idempotent replay/conflict, report validation/provenance, reconciliation blocking, leadership mutation denial and synthetic-only constraints.

The catalog is executable documentation. It does not certify execution until observable CI/local telemetry is available.

## Integrated Chain

`Command → Authorization → Idempotency → Transaction → Domain Workflow → Evidence/Audit → Reconciliation → Read Model → Dashboard/Preview → Approval → Artifact`

## Explicit Non-Goals

- No schema migration.
- No live database.
- No production credentials.
- No real detainee data.
- No AI activation.
- No direct operational mutation from a dashboard read model.
- No claim of execution certification without telemetry.
