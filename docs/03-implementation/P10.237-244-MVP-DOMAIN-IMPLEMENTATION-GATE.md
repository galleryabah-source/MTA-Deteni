# P10.237–P10.244 — MVP Domain Implementation Gate

## Status

- Checkpoint: **P10.244**
- Classification: **PLANNING_READY**
- Migration Freeze: **TRUE**
- AI: **OFF**

## Purpose

Establish the controlled transition from platform/kernel verification into implementation of the operational MVP without weakening the existing governance and security boundary.

## P10.237 — Domain order

Implementation order:

```text
Core Administration
  ↓
Placement / Block / Room / Bed
  ↓
Movement & Headcount
  ↓
Temporary Exit
  ↓
Escort
  ↓
Document Engine
  ↓
Approval / Leadership
  ↓
Reporting
```

## P10.238 — Detainee master boundary

Core detainee records must support identity, status history, provenance, verification/completeness, and classification. Restricted PERKES/health information remains outside the ordinary operational read path.

## P10.239 — Event/history rule

Critical records use append/event history. Corrections create controlled history rather than silently replacing material operational facts.

## P10.240 — Temporary-exit state machine

The implementation must preserve the approved conceptual flow:

```text
REQUESTED
 → VALIDATED
 → APPROVED
 → DOCUMENTED
 → ESCORT_ASSIGNED
 → DEPARTED
 → RETURN_PENDING
 → RETURNED
 → COMPLETED
```

Invalid transitions fail closed. Exact state names may only change through the approved domain contract.

## P10.241 — QR/barcode boundary

QR/barcode is an identification and workflow aid, not an authorization mechanism. A scan must resolve through server-side authorization, current state, actor, scope, and purpose.

## P10.242 — Document chain

Temporary exit remains coupled to the controlled document chain:

```text
Exit Request
 → Approval
 → Surat Izin Keluar Sementara
 → Escort Assignment
 → Surat Tugas Pengawalan
 → Departure
 → Return
 → Closure
```

Document generation does not itself authorize the underlying operational action.

## P10.243 — UI contract

The application shell should remain lightweight and responsive for desktop, tablet, and smartphone. Windows-11-inspired visual language is permitted at presentation level, while business rules remain server-side and device-independent.

## P10.244 — Implementation gate

Before coding each domain, require:

- domain contract;
- authority/action matrix;
- state machine;
- validation rules;
- audit events;
- idempotency behavior;
- error taxonomy;
- synthetic fixtures;
- test scenarios;
- document dependencies where applicable.

No domain implementation may bypass the kernel contracts.

## Safety invariant

> Domain features are consumers of the security and transaction kernels, never alternate paths around them.
