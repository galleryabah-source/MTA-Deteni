# P10.261–P10.268 — Movement & Headcount Contract

## Purpose

Define the authoritative operational event flow for detainee movement and headcount. Movement is event-based; headcount is a derived operational view with reconciliation controls.

## Rules

1. Every material movement records actor, source, destination/context, timestamp, reason/purpose, authorization context, and correlation/idempotency reference.
2. Movement state changes are atomic and use the transaction kernel.
3. A movement cannot create an impossible placement or bypass active-placement rules.
4. Headcount is derived from accepted current placement/movement state and must expose reconciliation exceptions.
5. Concurrent movement attempts against the same active state must use server-side predicates and fail closed for losers.
6. Historical movement events are immutable; correction is represented by controlled compensating events.
7. KAMTIB operational scope is enforced independently of UI filtering.
8. QR/barcode scans identify a detainee or operational object but never grant movement authority.
9. Export and reporting permissions are distinct from operational mutation permissions.
10. Audit/outbox evidence is coupled to successful state transition.

## Acceptance

Synthetic tests cover normal movement, concurrent movement, wrong scope, stale state, duplicate request, impossible destination, headcount reconciliation, compensating event, scan without authority, and audit failure rollback.

`Placement → Movement & Headcount → Temporary Exit`.
