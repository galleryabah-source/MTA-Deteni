# MTA DETENI — P10.61–P10.68 Persistence & Runtime Readiness

## Purpose

Convert the synthetic temporary-exit application boundary into a production-oriented contract without lifting Migration Freeze or touching PostgreSQL.

## P10.61 — Repository transaction semantics

A repository transaction must provide atomic commit/rollback semantics. Domain state, timeline, document metadata, artifact grant metadata, audit event and outbox intent must share the same critical transaction boundary when persistence is enabled.

## P10.62 — Idempotency

Every mutating temporary-exit command must carry an operation identity/idempotency key. A replay with the same canonical request returns the original result; a conflicting payload is rejected. Idempotency records must be scoped to actor, operation and resource context.

## P10.63 — Authorization at application boundary

The application service must receive server-derived actor identity, scope, duty and authorization context. Client-supplied actor/scope claims are never authoritative. Authorization is evaluated before mutation and again at sensitive artifact/download operations where required.

## P10.64 — Operational state vs detainee lifecycle

The temporary-exit operational state machine is an application workflow. It must not replace or silently redefine the detainee domain lifecycle. Mapping between the two is explicit and tested.

## P10.65 — Persistent timeline integrity

Timeline persistence is append-only. Sequence numbers are monotonic, terminal CLOSE prevents later events, and every event carries actor identity, scope/correlation context, timestamp, result and bounded metadata.

## P10.66 — Audit/outbox integration

Audit and outbox intents are part of the critical transaction. External providers are invoked only after successful commit. A provider failure cannot roll back the already committed business transaction; retry/dead-letter semantics live in the outbox worker.

## P10.67 — Artifact/download persistence

Issued documents and grants are persisted with immutable artifact identity/hash, actor/scope/object binding, expiry and consumption/revocation state. Download is single-use and fail-closed after expiry, revoke or consumption.

## P10.68 — Runtime readiness gate

The authenticated HTTP/API layer must expose the application service without direct browser database writes. Mutation routes require server session, CSRF protection where applicable, authorization, idempotency and transaction boundaries. Read routes return the unified read model subject to scope/classification controls.

## Safety boundary

- Migration Freeze remains TRUE.
- No migration is executed by these checkpoints.
- AI remains OFF.
- Synthetic fixtures/test doubles only.
- No provider activation.
- Certification remains NOT CERTIFIED until independent evidence exists.
