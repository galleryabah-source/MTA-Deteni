# P10.205–P10.212 — Read-Only Schema & RLS Contract Reconciliation

## Status

- Checkpoint: **P10.212**
- Classification: **BLOCKED_PENDING_GOVERNANCE**
- Mode: **READ_ONLY_RECONCILIATION**
- Migration Freeze: **TRUE**
- AI: **OFF**
- Data: **Synthetic only**

## Purpose

Define the final read-only reconciliation step between the approved logical/data contracts and a future controlled non-production PostgreSQL target. This checkpoint deliberately separates observation from migration.

## P10.205 — Contract inventory

Build an expected-object inventory from approved contracts:

- tables;
- columns and data types;
- nullability;
- primary/foreign keys;
- unique constraints;
- indexes;
- check constraints;
- RLS enablement;
- RLS policies;
- required audit/outbox structures;
- required metadata/version fields.

## P10.206 — Actual inventory

On an approved non-production target, capture only read-only catalog observations. No CREATE, ALTER, DROP, INSERT, UPDATE, DELETE, TRUNCATE, GRANT, or REVOKE operation is part of this checkpoint.

## P10.207 — Difference classification

Every difference must be classified as:

```text
MATCH
MISSING
EXTRA
DRIFT
UNKNOWN
```

No automatic remediation is allowed.

## P10.208 — Security reconciliation

Compare expected versus actual:

- RLS enabled state;
- policy predicates;
- role grants relevant to the application;
- restricted-domain boundaries;
- audit access controls.

Any security weakening is a hard BLOCK.

## P10.209 — Transaction-support reconciliation

Confirm the actual schema supports the previously approved transaction/idempotency contract, including required uniqueness, state predicates, timestamps, and audit/outbox coupling structures.

A missing supporting constraint is reported; it is not silently created.

## P10.210 — Migration decision gate

Only after reconciliation may a migration candidate be classified as:

```text
NO_MIGRATION_REQUIRED
MIGRATION_ARTIFACT_REQUIRED
BLOCKED_PENDING_CONTRACT_CHANGE
```

The gate never executes the migration.

## P10.211 — Evidence binding

The reconciliation report must bind:

- expected contract hash;
- observed catalog snapshot hash;
- RLS policy identity/hash;
- application commit SHA;
- environment flags;
- target reference;
- reviewer reference.

Sensitive credentials and operational data are excluded.

## P10.212 — Final reconciliation result

The result is one of:

```text
RECONCILED
DRIFT_DETECTED
BLOCKED
```

`RECONCILED` means expected and actual contracts are compatible for the defined verification scope. It does not authorize migration or production release.

## Safety invariant

> **Observe first. Decide second. Migrate only under a separately approved governance gate.**
