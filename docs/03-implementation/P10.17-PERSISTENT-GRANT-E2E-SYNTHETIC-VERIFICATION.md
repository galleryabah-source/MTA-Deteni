# P10.17 — Persistent Grant End-to-End Synthetic Runtime Verification

## Status

PREPARED — executable synthetic verification; no real database or production service required.

## Objective

Prove that the persistent artifact-grant flow preserves authorization, document binding, transaction atomicity, audit ordering and outbox isolation across the domain and runtime boundaries.

## Scenario

1. Construct a synthetic issued document with opaque subject/object identifiers.
2. Create a persistent artifact grant with actor and scope binding.
3. Execute grant creation through the transaction orchestration boundary.
4. Assert grant creation, audit append and outbox enqueue use one transaction context.
5. Simulate a provider/network action and assert it is not invoked before commit.
6. Consume the grant using matching actor/scope/object context.
7. Assert exactly one successful terminal transition.
8. Replay the same grant and assert denial/zero-row semantics.
9. Attempt wrong actor, wrong scope and wrong object and assert denial.
10. Revoke an active synthetic grant and assert subsequent consumption is denied.
11. Inject transaction failure and assert grant/audit/outbox rollback together.

## Evidence

Record only synthetic identifiers, operation class, correlation/causation IDs, transaction-double identity, affected-row count, lifecycle state and provider-call ordering. No sensitive payloads.

## Certification boundary

Passing the synthetic scenario does not constitute PostgreSQL, RLS, production storage, provider or production certification. Those require independent real-environment evidence after authorized execution.

## Safety

AI remains OFF. Migration Freeze remains TRUE. No DDL or production database operation is performed.
