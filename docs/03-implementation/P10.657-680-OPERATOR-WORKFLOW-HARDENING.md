# P10.657–P10.680 — Synthetic E2E, QR, Reporting and Operator Workflow Hardening

## P10.657–P10.664 — QR invariants
- QR is an operational verification mechanism, not a free-form data-entry channel.
- A stay QR is valid only within its defined Rudenim-stay validity window.
- Temporary-exit and deportation scans are distinct operational contexts.
- Inactive, expired, future-issued or context-incompatible QR values are rejected.

## P10.665–P10.672 — Reporting invariants
- Operational reports consume a versioned snapshot.
- Snapshot identity and source version are mandatory.
- Counts must be non-negative and structurally valid before rendering.
- Provenance remains attached to report data.

## P10.673–P10.680 — Operator workflow
The canonical temporary-exit operator flow is represented as one application workflow:

RAP request → KAMTIB validation → Leadership approval → SUBBAG TU document → KAMTIB escort assignment → departure → return → Leadership read-only oversight.

The workflow contract prevents duplicate step identifiers and preserves leadership oversight as read-only.
