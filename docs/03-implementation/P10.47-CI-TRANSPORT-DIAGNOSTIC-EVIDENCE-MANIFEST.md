# P10.47 — CI Transport Diagnostic & Evidence Manifest

Status: PREPARED / FAIL-CLOSED.

## Purpose

When GitHub Actions reports a failed job but step/log blobs are unavailable, the repository must retain enough non-secret diagnostic evidence to distinguish application assertion failure from CI transport/infrastructure loss.

## Diagnostic contract

The workflow records, without printing environment secrets:

- commit SHA;
- workflow run identifier;
- Node and npm versions;
- runner OS/architecture;
- presence of `package-lock.json`;
- presence/absence of `.env` and `.env.local`;
- configured safety values (`APP_ENV`, `AI_ENABLED`, `MIGRATION_FREEZE`);
- dependency install mode and status.

The diagnostic is uploaded with `if: always()` and is not a certification artifact by itself.

## Evidence semantics

- PASS: application evidence and transport evidence are independently observable.
- FAIL: application assertions are observable and fail.
- BLOCKED: required logs/artifacts are unavailable, contradictory, or safety evidence is incomplete.

A missing GitHub log blob must never be silently interpreted as an application PASS.

## Security

Do not dump `process.env`, tokens, credentials, provider responses, database URLs, request bodies, detainee data, or generated documents into diagnostics.

## Release boundary

P10.47 does not lift Migration Freeze, enable AI, activate providers, execute migrations, or certify production.
