# P10.22 — CI Evidence Hardening & Runtime Regression Gate

## Status

IMPLEMENTED — certification remains fail-closed pending independently observable GitHub Actions evidence.

## Objective

Create one deterministic CI entry point for the P10 synthetic runtime domain suite. The gate must distinguish application test failure from safety blocking and preserve evidence when the test command fails.

## Safety contract

The workflow is permitted to execute only when:

- `APP_ENV=test`;
- `AI_ENABLED=false`;
- `MIGRATION_FREEZE=true`;
- `.env` and `.env.local` are absent;
- only repository test fixtures and test doubles are used.

## Regression scope

The gate verifies the required P10.1–P10.16, P10.19 and P10.21 synthetic test files exist, then executes them through `node --test` as one deterministic suite.

## Classification

- `PASS`: all required files exist, safety contract is satisfied, and the complete suite exits successfully;
- `FAIL`: safety contract is satisfied and the complete suite exits unsuccessfully;
- `BLOCKED`: a safety condition or required-file precondition is not satisfied.

A classification is not production certification.

## Evidence

The gate emits:

- `artifacts/p10-runtime/classification.json`;
- `artifacts/p10-runtime/test-output.txt`.

Evidence contains only operational metadata, synthetic classification, test process status, commit/run identity supplied by GitHub, and a SHA-256 digest of the test output. No detainee data, document contents, credentials, tokens or secrets are intentionally emitted.

## Workflow behavior

Diagnostics are uploaded with `if: always()` so a failing regression suite cannot silently discard its evidence. `workflow_dispatch` is available for controlled manual reproduction without changing the safety environment.

## Non-goals

P10.22 does not lift Migration Freeze, execute migrations, connect to production databases, enable AI, weaken authorization/RLS, use real detainee data, or claim production readiness.
