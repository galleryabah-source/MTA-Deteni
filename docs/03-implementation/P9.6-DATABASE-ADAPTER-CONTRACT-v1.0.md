## Objective

`BLUEPRINT → EXPECTED DATABASE CONTRACT → ACTUAL REPOSITORY → ACTUAL DATABASE ENVIRONMENT → RUNTIME BEHAVIOR`

P9.6 does **not** create tables, alter columns, add constraints, or execute migrations.

## Non-Negotiable Rules

1. Domain code must not open database connections directly.
2. Domain code must not depend on ORM-specific APIs.
3. API handlers must not contain business SQL.
4. Repository methods expose intent, not arbitrary query construction.
5. Critical mutations execute inside explicit transactions.
6. Critical commands support idempotency where retries are possible.
7. Authorization is evaluated before policy-sensitive writes.
8. Database constraints are defense-in-depth, not a replacement for authorization.
9. Reporting connections/roles are read-only and cannot mutate canonical data.
10. AI processing has no canonical write capability.
11. Migration scripts are not runtime capabilities.
12. No production migration occurs during P9.6.

## Database Adapter Contract

```ts
export interface DatabaseAdapter {
  query<T>(operation: DbOperation<T>): Promise<T>;
  transaction<T>(fn: (tx: TransactionContext) => Promise<T>): Promise<T>;
  healthCheck(): Promise<DatabaseHealth>;
  close(): Promise<void>;
}
```

The concrete implementation may use PostgreSQL with an ORM or driver selected after repository audit. The contract must prevent infrastructure details from leaking into domain services.

## Transaction Contract

```ts
export interface TransactionContext {
  query<T>(operation: DbOperation<T>): Promise<T>;
  commit(): Promise<void>;
  rollback(): Promise<void>;
}
```

Application services should normally use a managed transaction helper so commit/rollback cannot be accidentally omitted.

Required properties:

- atomicity for related critical state changes;
- rollback on critical failure;
- consistent isolation policy;
- timeout protection;
- correlation ID propagation;
- audit/outbox handling according to the transaction policy;
- safe behavior under concurrent requests.

## Connection Lifecycle

Required checks:

1. connection creation is centralized;
2. pooling limits are configured;
3. connection timeout exists;
4. idle timeout exists where appropriate;
5. failed connections are discarded safely;
6. application shutdown drains the pool;
7. credentials are loaded only from environment/secret management;
8. credentials never enter logs;
9. health checks do not expose connection strings;
10. transaction timeout prevents indefinite locks.

## Reconciliation Status Codes

Each object is classified as:

- `MATCH` — expected and actual contract agree;

## Critical Leave/Handover Database Invariants

The implementation must be capable of enforcing, transactionally:

1. only an authorized active Duty Officer can complete the final leave return;
2. the leave must be in the handover-ready state;
3. the Security/Kamtib handover must exist;
4. duplicate receipt is prohibited;
5. concurrent finalization produces at most one successful completion;
6. movement return and leave completion remain consistent;
7. linked escort completion follows its own authority and policy;
8. overdue resolution occurs only after valid return receipt;
9. audit evidence is created for the critical mutation;
10. notification failure does not roll back a successful domain event unless the approved transaction policy explicitly requires it.
