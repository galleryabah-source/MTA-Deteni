# P10.12 — Database Integration Package

## Status

PREPARED — migration/RLS/integration package only. No DDL has been executed.

## Scope

This checkpoint converts the P10.11 readiness contract into an executable review package for the future approved PostgreSQL integration of `artifact_download_grants`.

The package is deliberately separated from deployment. `MIGRATION_FREEZE=TRUE` remains authoritative.

## Required integration sequence

`Schema Review → Migration Approval → Controlled Migration Window → Schema Verification → Repository Integration → RLS Verification → Concurrency Test → Rollback Drill → Evidence Review`

No step may be skipped merely because the application test suite passes.

## Database model

The proposed table stores only grant lifecycle and binding metadata:

- `grant_id`
- `document_id`
- `artifact_id`
- `artifact_sha256`
- `object_id`
- `actor_id`
- `scope_id`
- `issued_at`
- `expires_at`
- `status`
- `consumed_at`
- `revoked_at`
- `created_at`

The table does not store detainee names, health data, document contents, credentials, access tokens, or provider secrets.

## Security model

Application authorization remains authoritative. Database RLS is defense-in-depth and scope isolation; it is not a substitute for the application Authorization Control Plane. The existing ACP requires deny-by-default, policy evaluation, scope, duty, classification and SoD controls. fileciteturn69file0L2-L3
