# P11.001–P11.032 — Application Boundary Regression Gate

## Purpose

Extend the synthetic verification chain from execution-evidence shape into the application boundary without introducing production access, database writes, AI, or schema migration.

## Controls

- P11.001–008: supported UI surface identity;
- P11.009–016: every exposed UI mutation has an explicit server-bound action id;
- P11.017–024: responsive read-model collections remain structurally valid;
- P11.025–032: QR verification and report conversion remain application-bound capabilities.

## Boundary

The gate is synthetic-only. It does not execute against live PostgreSQL, production services, real detainee records, external messaging, or AI providers.

## Fail-Closed Rule

A missing gate identity, unknown surface, malformed read model, invalid mutation boundary, missing capability, or non-PASS check blocks the gate.

This checkpoint preserves the integrated MTA DETENI application model: RAP, PERKES, KAMTIB, SUBBAG TU, and HEAD RUDENIM remain governed through their existing application/domain boundaries rather than bypassed by UI code.
