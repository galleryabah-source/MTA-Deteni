# P10.18 — Document Output Operationalization Package

## Status

PREPARED — specification and synthetic contract only. No production document, detainee data, credential, signature material, or external provider is used.

## Objective

Formalize the two required MVP Word outputs and bind their generation to authorization, lifecycle, template governance, artifact integrity, private storage, approval/issuance and secure download handoff.

## Required outputs

1. `TEMPORARY_EXIT_PERMISSION` — Surat Izin Keluar Sementara.
2. `ESCORT_ASSIGNMENT_LETTER` — Surat Tugas Pengawalan.

The system must generate `.docx` artifacts from an approved template manifest. Templates are versioned and identified by deterministic template ID/version and SHA-256 checksum. The renderer must never accept arbitrary filesystem paths, executable template instructions, or untrusted macro content.

## Operational lifecycle

`DRAFT → PENDING_APPROVAL → APPROVED → ISSUED → ARCHIVED/VOID`

Generation may prepare a candidate artifact, but an official output is not considered issued until the document lifecycle reaches `ISSUED` under the existing authorization and separation-of-duties rules.

Required role boundaries remain:

- `PREPARER`: prepares document data and candidate artifact;
- `APPROVER`: approves the document independently;
- `ISSUER`: issues the approved document and binds the final artifact identity/hash;
- `ARCHIVER`: archives according to retention policy.

No single role may silently collapse these controls where SoD is required.

## Template governance

Each template manifest must define:

- document kind;
- template ID and immutable version;
- template SHA-256;
- field definitions and types;
- permitted data sources (`source_authorization`, `source_document`, `source_system`);
- required/optional fields;
- deterministic rendering rules;
- output metadata requirements.

Approved production templates and signature infrastructure remain a governance dependency. Until approved, tests use synthetic templates and opaque values only.

## Artifact integrity

Every issued artifact must have:

- opaque artifact ID;
- document ID binding;
- template ID/version binding;
- SHA-256 checksum of the final `.docx` bytes;
- creation/issuance timestamps;
- lifecycle state;
- storage state and classification;
- audit correlation/causation identifiers.

A checksum mismatch, missing artifact binding, invalid lifecycle state, or unauthorized actor must fail closed.

## Secure download handoff

Downloads use the existing persistent artifact-grant boundary. A grant is bound to:

- artifact ID;
- document ID;
- artifact SHA-256;
- object ID;
- actor ID;
- scope ID;
- expiry;
- single-use lifecycle.

Expected terminal semantics are `ACTIVE → CONSUMED` exactly once, or `ACTIVE → REVOKED`. Replay, wrong actor, wrong scope, wrong object, expired grant, revoked grant and artifact mismatch must deny access.

Provider/network delivery is downstream of transaction commit. No external provider call is allowed inside the critical transaction.

## Synthetic verification matrix

- D18.1 template manifest integrity;
- D18.2 deterministic field validation;
- D18.3 DOCX generation produces non-empty valid artifact bytes;
- D18.4 final artifact SHA-256 is stable for identical canonical input;
- D18.5 document lifecycle blocks issuance unless approval and authorization requirements are satisfied;
- D18.6 issuer cannot bypass required SoD;
- D18.7 artifact binding matches document/template/hash;
- D18.8 secure grant binds actor/scope/object/artifact;
- D18.9 download consumes a grant exactly once;
- D18.10 replay/wrong actor/wrong scope/wrong object/expired/revoked access is denied;
- D18.11 injected transaction failure leaves grant/audit/outbox uncommitted together;
- D18.12 provider/network is not invoked before commit;
- D18.13 evidence contains only opaque synthetic identifiers and operational metadata;
- D18.14 no arbitrary template path, macro execution, or untrusted content path is accepted.

## Evidence contract

Evidence records only test ID, synthetic document/artifact/grant IDs, template version/checksum, lifecycle state, actor/scope/object labels, affected-row count, transaction context identity, provider-call ordering, result class and correlation/causation IDs. No detainee PII, health information, document contents, credentials, tokens or provider secrets.

## Hard stops

The checkpoint is BLOCKED if any of the following is true:

- `MIGRATION_FREEZE=TRUE` for real database execution;
- approved production templates are absent when production output is attempted;
- artifact hash or document binding is missing/mismatched;
- authorization, scope, duty, classification or lifecycle checks are unavailable;
- SoD is violated or bypassed;
- secure grant context is incomplete;
- evidence destination cannot be safely persisted;
- provider/network would execute before transaction commit;
- synthetic verification cannot distinguish `PASS`, `FAIL`, `BLOCKED` and `SKIPPED_BY_SAFETY_GATE`.

## Explicit non-goals

P10.18 does not:

- execute a migration;
- connect to production PostgreSQL;
- create production templates;
- issue real documents;
- integrate real printers/scanners/signature devices;
- call external document providers;
- enable AI;
- weaken RLS/RBAC;
- alter `main`.
