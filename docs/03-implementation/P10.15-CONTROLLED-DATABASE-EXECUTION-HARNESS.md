# P10.15 — Controlled Database Execution Harness

## Status

PREPARED — execution is fail-closed while `MIGRATION_FREEZE=TRUE`.

## Objective

Define a controlled runner that can execute the already-reviewed database migration only after an explicit governance decision lifts the migration freeze and the target database is independently verified.

## Non-negotiable safety gates

The runner MUST stop before opening an execution connection when any condition is true:

- `MIGRATION_FREEZE=true`;
- execution approval is absent or invalid;
- target database identity is absent or does not exactly match the approved target;
- approved migration artifact or SHA-256 checksum is unavailable or mismatched;
- production execution mode is not explicitly selected by the authorized release process;
- identity/scope RLS contract has not been approved;
- evidence destination is unavailable;
- required connection policy or transaction controls are unavailable.

`SKIPPED_BY_SAFETY_GATE` is never PASS.

## Execution sequence

1. Load immutable execution manifest.
2. Verify freeze state.
3. Verify signed/recorded governance approval reference.
4. Verify target database identity.
5. Verify migration artifact SHA-256.
6. Verify migration version is not already applied.
7. Open the minimum-privilege execution connection.
8. Execute the approved migration in a controlled transaction where supported.
9. Verify schema, constraints, indexes, privileges and RLS state.
10. Run role/isolation verification using synthetic identities and synthetic grants only.
11. Record evidence before declaring the checkpoint complete.
12. Release the connection and preserve the evidence package.

## Production protection

The harness MUST NOT infer a production target from a URL, hostname pattern or environment name. The target identity must be independently queried and compared with the approved execution manifest. No wildcard or fallback target is permitted.

The harness MUST NOT accept client-provided SQL, migration paths, arbitrary table names or arbitrary connection strings as execution input.

## Evidence contract

Each execution record contains:

- run ID;
- approval reference;
- target database identity;
- migration artifact path/version/checksum;
- start/end timestamps;
- execution transaction identifier where safe;
- schema verification results;
- RLS/privilege verification results;
- role/isolation results;
- affected-row counts for transition tests;
- rollback result where tested;
- final status.

No detainee PII, health information, document contents, credentials, access tokens or provider secrets may enter the evidence record.

## Failure semantics

Any verification mismatch is terminal for the run. The harness records `BLOCKED`, `FAILED`, or `SKIPPED_BY_SAFETY_GATE` as appropriate and never converts an incomplete execution into PASS.

Provider/network calls remain outside critical database transactions and are not required for migration certification.

## Current checkpoint boundary

No migration is executed by P10.15 while the freeze remains TRUE. This document is an execution design and safety contract only.
