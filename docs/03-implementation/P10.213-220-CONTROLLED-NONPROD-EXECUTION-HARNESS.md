# P10.213–P10.220 — Controlled Non-Production Execution Harness

## Status

- Checkpoint: **P10.220**
- Classification: **BLOCKED_PENDING_GOVERNANCE**
- Execution: **NOT AUTHORIZED**
- Migration Freeze: **TRUE**
- AI: **OFF**
- Data: **Synthetic only**

## Purpose

Define the executable harness boundary for future controlled non-production PostgreSQL verification. The harness may prepare, validate, observe, and report, but must refuse live execution unless all explicit governance and environment gates are satisfied.

## P10.213 — Harness identity

Every run receives an immutable run ID, application commit SHA, contract version, environment identity, and evidence-manifest identity.

## P10.214 — Safety preflight

Before any database connection is opened, verify:

- target is explicitly approved non-production;
- governance clearance exists for the exact run;
- Migration Freeze state matches the approved operation;
- AI remains disabled;
- synthetic-only fixture mode is active;
- no production credentials or data are present;
- rollback owner and evidence destination are identified.

Failure is fail-closed.

## P10.215 — Capability boundary

The harness separates:

```text
OBSERVE
VERIFY
EXECUTE
```

`OBSERVE` and `VERIFY` may operate without mutation. `EXECUTE` is unavailable while governance authorization is absent.

## P10.216 — SQL allowlist

Controlled execution must use an explicit scenario allowlist. Ad-hoc SQL, destructive SQL, privilege changes, extension installation, schema mutation, and provider calls are prohibited unless separately approved by a future gate.

## P10.217 — Transaction wrapper

Each mutable verification scenario must expose:

```text
BEGIN
  precondition
  authorization predicate
  domain mutation
  audit/outbox coupling
COMMIT
```

Any unexpected failure produces `ROLLBACK` and a diagnostic evidence record.

## P10.218 — Fixture isolation

Fixtures are synthetic, deterministic, uniquely namespaced to the run, and disposable. Production identifiers, PII, health records, credentials, and operational exports are prohibited.

## P10.219 — Evidence capture

Capture run ID, scenario ID, affected-row counts, transaction result, state transition, audit/outbox evidence, environment flags, and artifact hashes. Never capture secrets or unnecessary sensitive payloads.

## P10.220 — Execution decision

The harness may return:

```text
BLOCKED
READY
EXECUTED_PASS
EXECUTED_FAIL
ABORTED
```

`READY` is not authorization. `EXECUTED_*` is impossible unless the explicit governance gate is satisfied.

## Safety invariant

> No governance clearance means no live mutation.
