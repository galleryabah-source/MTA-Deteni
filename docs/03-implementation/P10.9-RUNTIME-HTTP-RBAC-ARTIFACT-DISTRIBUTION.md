# P10.9 — Runtime HTTP/RBAC Artifact Distribution Boundary

## Status

IMPLEMENTED — synthetic/runtime boundary only. Production integration evidence remains pending.

## Objective

Connect the P10.8 controlled artifact-handoff contract to authenticated request context, deny-by-default authorization, private storage access, and transactional audit/outbox orchestration without weakening existing security invariants.

## Runtime flow

`Authenticated Request → Authorization → ISSUED/Artifact/Scope Validation → Critical Transaction (Audit + Outbox) → Commit → Outbox Worker → Storage Provider Grant → Single-use Download`

## Security invariants

- Permission: `deteni.document.artifact.download`.
- Authentication, active session, scope, assignment/duty, classification, resource state and policy are evaluated before distribution.
- Document must already be `ISSUED`.
- Document artifact ID, SHA-256 and private storage object ID must remain bound.
- Storage access is scope- and classification-bound.
- Audit and outbox are transaction participants; production adapters must execute them on the same critical transaction connection.
- Provider/network storage calls are explicitly excluded from the critical transaction and may execute only after a durable outbox claim/commit.
- Download grants remain actor-bound, scope-bound, time-limited and single-use.
- Replay, wrong actor, wrong scope, invalid state and checksum mismatch fail closed.
- Super Admin does not gain an operational bypass through this boundary.
- No production credentials, real detainee data, or official production documents are used by the tests.
- AI remains OFF and is not a distribution dependency.

## Test coverage

`test/p10.9-artifact-distribution.test.mjs` covers:

1. provider is not called inside the request/transaction boundary;
2. provider execution is separated as a post-commit worker action;
3. missing permission, wrong scope and non-ISSUED state are denied;
4. bound actor/scope/object and single-use consumption are enforced.

## Explicit non-certification

P10.9 does not certify real HTTP middleware, PostgreSQL transaction/isolation/concurrency, persistent grant state, production object storage, external provider idempotency/retry, or deployment. Those require independently observable integration evidence before certification.
