## Boundary

Flow:

`Request Context → Authorization → Domain Command → Transaction → Audit → Outbox`

## Implemented

- detainee temporary-exit lifecycle boundary;
- explicit state-transition contract;
- temporary-exit application command;
- authorization before domain mutation;
- transactional domain + audit + outbox boundary;
- idempotent replay protection;
- negative authorization path with zero side effects;
- synthetic executable integration tests.

## Safety

No production database, migration, real detainee data, production credentials, or external provider is used.
AI remains OFF and migration freeze remains active.

## Limitation

The current transaction store is an in-memory test double. It proves orchestration and rollback semantics but is not evidence of PostgreSQL isolation/locking behavior. Real database integration remains a separate gate.
