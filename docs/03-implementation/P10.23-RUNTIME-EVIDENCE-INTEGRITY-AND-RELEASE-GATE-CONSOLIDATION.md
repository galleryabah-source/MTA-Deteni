# P10.23 — Runtime Evidence Integrity & Release-Gate Consolidation

## Status

IMPLEMENTED — certification remains fail-closed pending independently observable GitHub Actions evidence.

## Objective

Ensure CI evidence cannot be mistaken for an unverified or production certification result. Evidence must be structurally valid, synthetic-only, bound to the tested commit, and internally consistent.

## Integrity checks

The evidence integrity gate verifies:

1. the supported evidence schema and current checkpoint `P10.140`;
2. `syntheticOnly=true`;
3. `APP_ENV=test`, `AI_ENABLED=false`, and `MIGRATION_FREEZE=true`;
4. a positive integer required-test count and zero missing required tests;
5. classification is one of `PASS`, `FAIL`, or `BLOCKED`;
6. the evidence commit matches `GITHUB_SHA` when running in GitHub Actions;
7. the SHA-256 digest of recorded test output matches the evidence digest.

The gate deliberately does not hard-code an obsolete test count. The regression manifest remains the authoritative source for the current suite.

## Separation of concerns

The regression gate determines the application-suite classification. The evidence gate determines whether that classification is trustworthy as CI evidence. A `PASS` evidence-integrity result does not convert a `FAIL` or `BLOCKED` regression classification into `PASS`.

## Safety

No database migration, production database connection, real detainee data, AI activation, provider invocation, credential handling, or authorization/RLS weakening is permitted by this checkpoint.

## Release interpretation

The only acceptable production interpretation is:

`CI evidence PASS` + all independent production certification blockers cleared + explicit governance approval.

Anything less remains `NOT CERTIFIED`.
