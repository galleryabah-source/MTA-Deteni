# P10.44 — Production Cutover / Rollback Gate

**Default disposition:** BLOCKED.

## Cutover gate

Production cutover may proceed only when all are true:

- governance decision explicitly authorizes controlled execution;
- migration and RLS bundles are immutable and hash-verified;
- target identity is independently verified;
- backup and restore evidence exists;
- PostgreSQL/RLS/concurrency evidence is PASS;
- deployed authentication and RBAC enforcement are PASS;
- document templates, deterministic DOCX rendering, approval/issuance lifecycle and private artifact handoff are PASS;
- audit and outbox persistence are PASS;
- storage/provider security is PASS;
- WhatsApp webhook/provider and scanner/device boundaries are verified;
- monitoring, alerting, backup, DR and provider retry/dead-letter/idempotency are verified;
- production owner and rollback owner are distinct where required by SoD;
- certification authority explicitly records release disposition.

## Rollback gate

Rollback must be triggered for schema mismatch, RLS bypass, unauthorized access, audit-chain inconsistency, transaction atomicity failure, artifact binding failure, provider calls occurring before commit, loss of required evidence, or unexplained production data mutation.

Rollback sequence: stop affected writes/workers → preserve evidence → isolate affected component → invoke approved rollback plan → verify database/application consistency → re-run security/integrity tests → record incident and disposition.

## No automatic activation

Neither CI PASS nor governance approval alone activates production. Technical execution and certification remain separate gates. If evidence is incomplete, the release stays BLOCKED.
