# P10.43 — Post-Freeze Verification Evidence Contract

This contract defines evidence required after, and only after, an authorized freeze-lift decision. It does not authorize execution.

## Evidence envelope

Required fields:

- `schemaVersion`
- `checkpoint`
- `decisionId`
- `commitSha`
- `targetEnvironment`
- `targetDatabaseIdentity`
- `migrationBundleSha256`
- `rlsBundleSha256`
- `backupId`
- `backupVerifiedAt`
- `schemaInventorySha256`
- `rlsVerificationSha256`
- `concurrencyEvidenceSha256`
- `runtimeEvidenceSha256`
- `negativeSecurityTests`
- `providerIsolationEvidence`
- `generatedAt`
- `operatorRole`
- `reviewerRole`

## Evidence semantics

`PASS` means the cited evidence exists, is internally consistent, is bound to the expected commit/environment, and can be independently inspected. `FAIL` means a required control was tested and failed. `BLOCKED` means execution/evidence was not legitimately possible because a prerequisite was absent. These classifications must never be collapsed.

## Minimum negative evidence

The package must demonstrate denial for unauthenticated requests, wrong actor, wrong scope, inactive duty, disallowed classification, invalid lifecycle state, revoked/expired/consumed artifact grants, duplicate idempotency with conflicting payload, and Super Admin operational bypass attempts.

## Database evidence

Real PostgreSQL evidence must include transaction boundaries, isolation/concurrency outcomes, row counts for atomic state transitions, RLS policy behavior, privilege inventory, and rollback behavior. Synthetic test doubles are not substitutes for this checkpoint.

## Integrity

Every evidence file is hashed. The evidence manifest itself is hashed last. A mismatch, missing artifact, timestamp inconsistency, environment mismatch, or unverifiable target identity yields BLOCKED.
