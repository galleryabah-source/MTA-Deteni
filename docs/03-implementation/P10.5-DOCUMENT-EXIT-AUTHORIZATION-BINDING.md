# MTA DETENI — P10.5 Document / Exit Authorization Binding

**Status:** IMPLEMENTED / EXECUTION EVIDENCE PENDING  
**Data boundary:** SYNTHETIC ONLY  
**Migration freeze:** TRUE  
**AI:** OFF

## Objective

Bind an operational document artifact to the authorization that permits the underlying action, while preserving lifecycle, separation of duties, integrity, and audit invariants.

## Required MVP outputs

P10.5 establishes two first-class document kinds:

1. `TEMPORARY_EXIT_PERMISSION` — Surat Izin Keluar Sementara.
2. `ESCORT_ASSIGNMENT_LETTER` — Surat Tugas Pengawalan.

The eventual renderer must produce Word `.docx` artifacts from approved templates. The document domain must not treat a generated file as authoritative by itself: authorization, document contract/version, template/version, artifact identity and SHA-256 integrity remain bound together.

## Binding contract

Each document record carries:

- immutable document ID;
- synthetic opaque subject reference;
- authorization ID;
- document contract version;
- template ID and template version;
- artifact ID and SHA-256 digest;
- organizational scope;
- correlation ID;
- lifecycle state and revision number.

No client-supplied boolean such as `isAuthorized` may substitute for the authorization engine. The document record cannot become `ISSUED` unless authorization and verified artifact bindings exist.

## Lifecycle

`DRAFT → PENDING_APPROVAL → APPROVED → ISSUED → ARCHIVED`

Terminal `VOID` is available from active states where operational cancellation is permitted by policy. `ARCHIVED` and `VOID` are terminal.

Role separation:

- `PREPARER` creates/submits;
- `APPROVER` approves;
- `ISSUER` issues;
- `ARCHIVER` archives.

The same role is not implicitly granted all transitions. Existing RBAC/ABAC, scope, duty, classification and SoD controls remain mandatory.

## Transaction boundary

The production persistence implementation must commit, atomically where applicable:

1. document lifecycle mutation;
2. audit event;
3. outbox event;
4. idempotency result.

External provider calls or distribution must occur only after transaction commit through the outbox boundary.

## Word artifact contract

The renderer/storage layer is responsible for:

- selecting an approved template version;
- deterministic merge of authorized fields;
- producing `.docx`;
- calculating SHA-256;
- storing the artifact under private access controls;
- exposing a controlled download grant to KAMTIB/TU according to authorization;
- retaining version/history and audit evidence.

No real template, detainee data, signature credential, or production artifact is committed at this checkpoint.

## Security invariants

- Authorization is checked before issuance.
- Artifact integrity is verified by SHA-256.
- Document and artifact identities are immutable once bound.
- Scope and classification remain enforced at retrieval/download.
- Revoked/expired authorization cannot be silently converted into an issuable document.
- AI is not required for generation, approval, issuance, or download.
- Migration freeze is not weakened.

## Current implementation boundary

`src/domain/document-lifecycle.mjs` provides the database-neutral lifecycle and binding invariants. `test/p10.5-document-lifecycle.test.mjs` provides synthetic executable coverage.

The following remain deliberately outside this checkpoint: PostgreSQL persistence, binary `.docx` generation, real storage provider integration, production RBAC/HTTP integration, digital-signature infrastructure, and production certification.
