# P12.521–680 — Persistence and Projection Integrity Gate

## Scope

This gate extends the MTA DETENI persistence boundary without enabling live database execution.

### P12.521–560
- Persistence repository operations carry transaction, actor and correlation identity.
- Existing versioned, append-only and outbox repository contracts remain compatible.
- Missing operation identity is blocked before persistence work.

### P12.561–600
- Idempotency observations preserve key, actor, correlation and aggregate identity.
- Outcomes distinguish acquire, replay, conflict, completion and failure.
- No observation is treated as authorization or operational evidence by itself.

### P12.601–680
- Projection progress is represented by an explicit checkpoint.
- Projection is downstream of committed outbox evidence.
- Projection can be replayed/rebuilt from evidence.
- Checkpoint advancement occurs only after successful projection.
- Retryable and permanent projection failures are distinct.

## Safety Boundary

- Migration Freeze: TRUE.
- AI: OFF.
- Repository data: SYNTHETIC ONLY.
- Production access: NOT AUTHORIZED.
- Live PostgreSQL execution: BLOCKED pending explicit governance clearance and approved non-production target.

These are contracts and controlled test boundaries, not database execution certification.

## Integrity Chain

`API → Authorization → Transaction Identity → Idempotency → Domain Mutation → Audit/Timeline → Outbox → Projection Checkpoint → Read Model → Reporting`

The outbox remains the durable hand-off boundary. A read model is never promoted to authoritative operational evidence.
