# P11.817–P11.960 — Operational Integrity Gate

## Scope

This gate composes four controls that must remain one application boundary:

1. immutable operational timeline;
2. audit/outbox correlation binding;
3. idempotency-aware mutation identity;
4. deny-by-default authorization regression.

## Invariants

- Timeline events are ordered, aggregate-bound, identified, and append-only at the contract level.
- A duplicate timeline event identifier is rejected rather than appended again.
- Audit and outbox records must carry non-blank correlation and aggregate identity.
- The same correlation/aggregate pair represents one operational transaction context; audit/outbox identifiers may differ.
- A mutation requires an idempotency key, request fingerprint, actor identity, and correlation identity before it can be admitted to a mutation boundary.
- A new fingerprint acquires an idempotency key; the same fingerprint replays; a different fingerprint conflicts.
- Authorization is deny-by-default and domain ownership is checked before a mutation is admitted.
- These are contract-level controls and do not claim database execution or production certification.

## Integrated flow

`Actor → Authorization → Idempotency → Domain Mutation → Immutable Timeline/Audit → Outbox → Read Model/Report`

The UI must not bypass this sequence for operational mutations.

## Safety

Migration Freeze remains TRUE. AI remains OFF. Repository data remains SYNTHETIC ONLY. Production access remains NOT AUTHORIZED. No schema migration, live PostgreSQL execution, real detainee data, or autonomous AI decision-making is introduced.

## Execution boundary

The repository currently has no trustworthy CI telemetry for the newly written commits. Therefore this gate is **CONTRACT-READY / EXECUTION TELEMETRY REQUIRED**, not CI-PASS.
