## End-to-end contract

```text
Detainee
 → Placement
 → Movement/Headcount
 → Temporary Exit Request
 → Validation
 → Approval
 → Exit Document
 → Escort Assignment
 → Escort Document
 → Departure
 → Return
 → Closure
 → Timeline / Audit
```

## Required cross-domain invariants

1. One stable detainee identity is used across all operational domains.
2. Placement and movement state cannot contradict one another.
3. Temporary exit cannot bypass approval or required escort prerequisites.
4. Documents are projections/artifacts of accepted workflow states, never authorization substitutes.
5. QR/barcode cannot bypass authorization.
6. Audit/outbox evidence accompanies every material mutation.
7. Idempotency prevents duplicate transitions and official-number allocation.
8. Restricted PERKES data remains isolated throughout API, service, UI, export, and reporting paths.
9. Historical facts remain reconstructable.
10. Any security, integrity, or transaction ambiguity fails closed.

## Test matrix

Synthetic E2E scenarios must include happy path, validation failure, approval denial, expired request, revoke race, concurrent departure, wrong actor, wrong scope, missing escort, document-generation failure, return exception, duplicate replay, restricted-field access attempt, audit failure, and recovery/rollback behavior.

## Release gate

No production or live sensitive-data activation follows from this document alone. Results must feed the existing evidence chain and remain subject to governance, UAT, security, backup/restore, and pilot gates.
