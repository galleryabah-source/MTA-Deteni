# P10.101–P10.108 Controlled Integration Boundary

## Purpose

Connect the authenticated HTTP boundary to the existing temporary-exit application boundary without opening PostgreSQL, providers, or production data.

## P10.101–P10.103 — HTTP command composition

The HTTP gateway authenticates the session, verifies CSRF for mutations, evaluates authorization, then composes a command from the server-side principal. Actor and scope supplied by the client are never authoritative. Mutation commands require an idempotency key.

## P10.104–P10.105 — Application/persistence boundary

The unified temporary-exit service is executable against the synthetic persistent adapter. Scope is asserted before the mutation boundary. This proves the composition boundary without claiming production persistence.

## P10.106 — Request traceability

Request ID and correlation ID survive command composition and are passed to the application handler so downstream audit/evidence systems can correlate a material command.

## P10.107–P10.108 — Provider isolation

Provider/network operations remain outside the transaction boundary. The synthetic adapter intentionally exposes no WhatsApp, external publication, or device-sync operation surface.
