# P10.333–P10.340 — Temporary Exit Implementation Scaffold

## Status

- Classification: **SCAFFOLD_READY**
- Migration Freeze: **TRUE**
- AI: **OFF**
- Data: **Synthetic only**

## State-driven service

```text
Request
 → Validate
 → Approve
 → Document
 → Assign Escort
 → Depart
 → Return Pending
 → Returned
 → Completed
```

Required operations: requestExit, validateExit, approveExit, revokeExit, expireExit, bindExitDocument, assignEscortReference, recordDeparture, recordReturn, completeExit, getExitTimeline.

Every transition must verify actor, authority, scope, current state, expiry/revocation, and idempotency. Departure must not succeed without the required approved/documented/escort prerequisites. QR/barcode is only a lookup/workflow signal.

## Concurrency

Departure, revoke, and expiry races must be resolved by server-side atomic predicates. Only one valid transition wins; losers receive a deterministic conflict/state response without partial mutation.

## Test gate

Synthetic E2E tests cover happy path, validation rejection, approval denial, expiry, revoke race, concurrent departure, missing escort, wrong actor, wrong scope, duplicate replay, and rollback.

## Safety

No migration or live database mutation is authorized by this scaffold.
