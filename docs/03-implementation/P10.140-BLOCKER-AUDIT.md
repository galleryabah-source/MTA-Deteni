# P10.140 — Blocker Audit and Remediation Record

## Purpose

Record the blockers discovered while hardening MTA DETENI as one governed application. This document separates application defects, repository defects, CI execution failures, dependency reproducibility gaps, and governance blockers. No blocker is marked resolved without observable evidence.

## Findings

| ID | Finding | Classification | Action | Status |
|---|---|---|---|---|
| B-01 | P9/P10 GitHub Actions jobs failed with no executable steps and unavailable job logs | CI execution infrastructure | Preserve failure; do not misclassify as application test failure | OPEN / external |
| B-02 | Repeated later check-runs also failed within seconds without executable step evidence | CI execution infrastructure | Treat as runner/evidence transport blocker; continue fail-closed | OPEN / external |

| B-04 | P10 evidence integrity gate still expected P10.22/P10.23-era checkpoint/count | Evidence-gate drift | Align integrity verification with P10.140 and validate structural count rather than stale literal count | RESOLVED |

| B-06 | Live PostgreSQL verification has not been independently observed | Governance / verification | Keep Migration Freeze TRUE; require approved non-production target and explicit clearance | OPEN |

## CI execution interpretation

A GitHub Actions `failure` without executable steps, logs, or artifacts is not sufficient evidence of a failing test assertion. The correct classification is an infrastructure/evidence blocker. The system must not weaken gates to make such a run appear successful.

## Dependency boundary

The repository currently declares `pg`, TypeScript, Node types, and Vitest dependencies, but no committed `package-lock.json`. The temporary CI bootstrap is acceptable only for development/regression preparation. It is not equivalent to reproducible dependency certification. A lockfile must be generated from a network-capable, reviewable dependency resolution and committed with its integrity data; no offline guesswork is permitted.

## Evidence-gate hardening

The regression gate remains the authoritative test manifest. The integrity gate now verifies the current P10.140 checkpoint, safety flags, synthetic-only status, positive integer test count, absence of missing tests, classification, commit binding when supplied by GitHub, and test-output SHA-256. This prevents an old literal checkpoint/test-count expectation from invalidating current evidence while retaining fail-closed integrity checks.

## Governance boundary

Migration Freeze remains TRUE. No schema migration, RLS deployment, live PostgreSQL write, production database connection, provider activation, AI activation, or production certification is authorized by this remediation record.

## Release rule

The project remains **NOT CERTIFIED** until all external CI evidence blockers, dependency reproducibility requirements, and governed PostgreSQL verification prerequisites are cleared with independently observable evidence.
