# MTA DETENI — P10.5 Temporary Exit Approval / Execution Boundary

**Status:** Executable foundation / NOT CERTIFIED  
**Data:** Synthetic only  
**AI:** OFF  
**Migration:** Frozen

## Objective

Establish a fail-closed approval boundary between a temporary-exit request and operational execution.

## Flow

`EXIT_REQUESTED → Validation → Authorization → Approval → EXIT_APPROVED → Audit → Outbox`

## Controls

- approval is only valid for `EXIT_REQUESTED`;
- approver identity is explicit;
- actor and approver must be different;
- purpose is controlled by an explicit allow-list;
- authorization is independent from request/identity data;
- successful approval crosses the transactional boundary;
- audit and outbox are critical side effects;
- idempotency prevents duplicate approval effects;
- no DOCX is issued by this domain command before the document contract and approval/numbering controls are implemented.

## Important boundary

P10.5 does not claim final legal/SOP approval semantics. Actual approver authority, document numbering, template version, signature metadata, departure/return execution and DOCX generation remain governed by the approved D1/D5 contracts.

## Certification blockers

Real PostgreSQL concurrency, runtime RBAC, approved authority matrix, document contract/template, storage, production deployment and CI evidence remain outstanding.
