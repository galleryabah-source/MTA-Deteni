# MTA DETENI — P13.4201–P13.4440 Release Integration

## Purpose

This checkpoint closes the next release-candidate contract layer as one integrated application. It does not authorize production deployment, live PostgreSQL execution, schema migration, real detainee data, or AI.

## Checkpoints

- **P13.4201–4240 — Integrated executable harness:** combines prior release controls and requires execution plus unique output identity for every control.
- **P13.4241–4280 — Report rendering verification:** verifies approved-template prerequisites, deterministic input, source/value reconciliation, element identity, ordering, and geometry evidence. This remains a verification boundary; exact visual reproduction is not claimed without observable rendered evidence.
- **P13.4281–4320 — End-to-end role journey matrix:** covers operational and governance roles, deny-by-default behavior, explicit outcomes, and the rule that HEAD_RUDENIM cannot mutate operational data.
- **P13.4321–4360 — Offline continuity drill:** validates local server readiness, trusted LAN clients, offline read-only behavior, ordered replay, human-reviewed conflicts, revoked-device rejection, and verified restore.
- **P13.4361–4400 — Release evidence manifest:** binds requirement → contract → evidence → output → telemetry and rejects NOT_RUN/FAIL as certification evidence.
- **P13.4401–4440 — Integrated pre-release gate:** requires all five control families while retaining migration freeze, AI OFF, production authorization OFF, and live database approval OFF.

## Architecture Integrity

The application remains one system with domain ownership preserved:

- RAP: registration, administration, reporting;
- PERKES: health records and health workflows;
- KAMTIB: placement, movement, headcount, temporary exit, escort, operational QR;
- SUBBAG TU: escort document administration;
- HEAD RUDENIM: oversight/directive/read-only visibility, without operational mutation.

Offline capability is continuity infrastructure, not a bypass of authorization. QR remains contextual operational verification. Temporary exit remains distinct from deportation.

## Evidence Rules

A control is not certified merely because its source file exists. Evidence must carry execution identity and output identity. The manifest also requires telemetry identity. `NOT_RUN` is never promoted to `PASS`.

## Safety Boundary

`migrationFreeze=true`, `aiEnabled=false`, `productionAuthorized=false`, `liveDatabaseApproved=false`, and `syntheticOnly=true` remain hard release prerequisites. No schema migration is introduced by this checkpoint.

## Next Gate

The next phase should convert these contracts into observable execution evidence in an approved non-production environment. If execution infrastructure is unavailable, the project remains contract-ready but execution-uncertified.
