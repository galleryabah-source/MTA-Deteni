## State machine

```text
REQUESTED
 → VALIDATED
 → APPROVED
 → DOCUMENTED
 → ESCORT_ASSIGNED
 → DEPARTED
 → RETURN_PENDING
 → RETURNED
 → COMPLETED
```

Invalid transitions fail closed.

## Rules

1. A request contains detainee, purpose, destination/context, requested window, requester, and provenance.
2. Validation checks completeness, active status, current placement, conflicts, authority, and applicable prerequisites.
3. Approval is a distinct authorization event and is never implied by request creation or document generation.
4. Documentation binds the approved request to the effective Surat Izin Keluar Sementara template/version.
5. Escort assignment must exist before departure where escort is required.
6. Departure and return are material operational events and cannot be silently edited.
7. QR/barcode scanning at departure/return resolves identity and current workflow state, then performs server-side authorization checks.
8. Expired, revoked, completed, wrong-scope, or wrong-actor requests cannot be consumed.
9. Concurrent consume/revoke/departure operations use atomic predicates; only one valid transition may succeed.
10. Every mutation is auditable, idempotent, and transactionally coupled to audit/outbox behavior.

## Acceptance

Synthetic tests cover validation failure, approval denial, expiry, revoke race, concurrent departure, missing escort, wrong actor/scope, QR scan without authority, return, duplicate replay, and rollback.
