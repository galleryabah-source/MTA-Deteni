# P10.27 — Authorization Enforcement Adapter Contract

Status: PREPARED — no production activation.

## Contract

Every protected runtime command must obtain an authenticated context and call the existing authorization kernel before domain mutation or sensitive resource disclosure.

```text
HTTP
 ↓
AuthenticatedContext
 ↓
authorize(request)
 ↓
DENY → generic external response + audit
ALLOW → validate input → domain command
```

## Required context

`userId`, `sessionId`, active status, effective permissions, scope, operational assignment/duty, classification clearance and policy version are resolved server-side. Client-provided role, scope, duty or classification claims are never authoritative.

## Deny-by-default

Missing or malformed security context produces denial. Super Admin status cannot satisfy operational duty requirements. Authorization decisions expose a stable internal reason code and policy version.

## Critical command boundary

For critical mutations: authorization → validation → domain mutation → mandatory audit → outbox, inside the transaction contract already established by P9/P10. Provider/network activity occurs only from committed outbox work.

## Non-goals

No identity provider, production session store, database policy, migration, provider, or real data is activated here.
