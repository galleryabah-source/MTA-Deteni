# P9.9 — Canonical Identity Hardening

Status: IMPLEMENTED — REPOSITORY-ONLY

## Objective

Formalize one identity chain across the canonical mutation, audit, outbox, dispatch and projection/publication seams without introducing a second persistence model.

## Canonical chain

`request_id → command_id → transaction_id → correlation_id → idempotency_key → event_id → audit_event_id → delivery_identity → projection_identity`

The chain is bound to one aggregate identity:

`aggregate_type + aggregate_id`

and one payload fingerprint.

## Invariants

1. Audit and outbox must reference the same aggregate type and aggregate id as the command.
2. Audit correlation id must equal the execution correlation id.
3. Outbox idempotency key must equal the execution idempotency key.
4. Replay must preserve event id, idempotency key, aggregate identity and payload fingerprint.
5. Downstream delivery/projection identities may be absent before those seams exist, but once present they are immutable members of the same chain.
6. Identity drift fails closed.
7. The contract is an application/evidence boundary only; it does not provision persistence or alter production RPC behavior.

## Scope boundary

- Repository-only.
- Synthetic-only fixtures.
- No migration.
- No production database execution.
- No lease-expiry change.

## Current hardening state

The projection seam is now bound directly to `OutboxEventContract` and no longer accepts the legacy `OutboxMessage` vocabulary. Projection results preserve the canonical `eventId + aggregateId` identity, while the full execution context and payload fingerprint remain available to the projection consumer.

The legacy persistence `OutboxMessage/OutboxRepository` abstraction remains under review. It must not be duplicated with a parallel runtime implementation; any retirement must replace the existing seam atomically at the repository contract boundary and preserve the canonical outbox lifecycle.

## Next gate

Re-run observable CI against the updated head and perform a second forensic pass. Lease-expiry remains a separate governed hardening item and is unchanged.
