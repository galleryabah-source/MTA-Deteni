# P9.8 Outbox Hardening — Current Baseline

## Scope
Advance the canonical outbox dispatcher onto the current P9.7 transaction/idempotency baseline without schema mutation.

## Runtime chain
Mutation -> PostgreSQL transaction -> audit -> outbox -> dispatcher claim -> deterministic payload validation -> internal application dispatch acceptance -> PUBLISHED.

## Hardening
- service-role credentials remain server-side;
- only POST is accepted;
- batch limit is bounded to 25;
- requested lease seconds are bounded to 15..300;
- event identity must match outbox event_id;
- idempotency identity must match outbox idempotency_key;
- required audit/request identity fields are mandatory;
- successful dispatch completes the outbox event;
- failures release with bounded retry backoff.

## Deferred / governance
The production claim RPC currently accepts p_lease_seconds but the previously audited implementation does not yet apply that parameter to the persisted lease calculation. This remains a deferred database hardening item from P9.6/P9.7 and is intentionally not changed here because MIGRATION_FREEZE=TRUE.

No schema change, migration, or production deployment is included.
