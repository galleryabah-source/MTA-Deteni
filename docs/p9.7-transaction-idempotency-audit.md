## P9.7-A — Transaction boundary

### Repository contract

`runSqlTransaction()` requires transaction metadata containing:

- transactionId
- actorId
- correlationId
- aggregateId

It begins through an injected `SqlTransactionFactory`, executes the work callback, commits on success, and rolls back on failure.

Status: **CONTRACT PASS / PRODUCTION IMPLEMENTATION NOT YET BOUND**

### Local implementation

`transaction-idempotency.mjs` provides a test/runtime scaffold using explicit BEGIN / COMMIT / ROLLBACK calls.

Status: **TEST SCAFFOLD — NOT PRODUCTION DATABASE ADAPTER**

## P9.7-B — Durable idempotency

Production mutation requests enter through the Supabase Edge Function bridge and call `mta_execute_idempotent_mutation`.

The production function validates:

- service-role execution
- minimum idempotency-key length
- SHA-256 request-hash format
- supported mutation operation
- allow-listed mutation tables
- JSON-object payload/where contracts
- primary-key targeting for UPDATE/DELETE
- audit metadata

The durable idempotency table has:

- primary key: `idempotency_key`
- status check: `COMPLETED`

The mutation function locks an existing key with `FOR UPDATE`, detects request-hash conflicts, replays an already completed response, executes the mutation, writes audit/outbox records, and only then stores the completed response.

Status: **PRODUCTION CONTRACT PASS**

## P9.7-C — Atomicity assessment

The production idempotency function performs the mutation, audit insert, outbox insert, and idempotency completion update within the same PostgreSQL function invocation.

Because the operation is executed as a PostgreSQL function call, the database transaction boundary is the function invocation.

Status: **PASS — VERIFIED BY FUNCTION STRUCTURE**

Important distinction: this does not yet prove end-to-end fault injection under a live production failure. Such testing is a later P9.7 regression gate.

## P9.7-D — Replay semantics

Expected behavior:

1. First request with a new key + hash executes once.
2. Same key + same hash returns the stored response with `replayed=true`.
3. Same key + different hash returns `IDEMPOTENCY_CONFLICT`.
4. A failed mutation does not authorize a successful completed replay.
5. Audit and outbox records are part of the same atomic mutation boundary.

Status: **CONTRACT PASS**
