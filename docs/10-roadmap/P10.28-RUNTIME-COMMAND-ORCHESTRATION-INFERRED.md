# P10.28 — Runtime Command Orchestration

Status: CONTRACT / INFERRED

## Purpose

P10.28 is the application-layer convergence point for authorization, idempotency, domain-state validation, runtime persistence readiness, mandatory audit, and conditional outbox readiness.

It is deliberately a decision boundary, not a persistence implementation.

## Execution order

1. Authorization.
2. Idempotency conflict/replay handling.
3. Domain-state validation.
4. Runtime readiness.
5. Mandatory audit availability.
6. Required outbox availability.
7. EXECUTE.

A replay never re-executes the command. A conflict never executes. Any unavailable required infrastructure fails closed.

## Envelope

Every command requires:

- requestId
- correlationId
- idempotencyKey
- actorId
- policyVersion
- commandType

## Relationship to earlier contracts

This contract composes concepts established by P9.4 authorization, P9.7 transaction/idempotency, P9.8 outbox, P9.19/P9.20 repository boundaries, and the P9.27–P9.31 runtime persistence contracts.

It does not replace the authoritative authorization kernel or concrete repository/runtime implementation.

## Safety

No database connection, SQL execution, schema migration, production mutation, external transport, storage upload, or AI call is performed.

The P10.28 label is a sequencing inference; it is not an authoritative checkpoint label found in the supplied source.
