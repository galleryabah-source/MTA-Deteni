# P10.4 — Leave Domain Contract

Status: contract implementation.

## Source basis

The P9/P10 source sequence identifies LEAVE as the next domain after DETAINEE, PLACEMENT, and MOVEMENT. The master roadmap defines temporary exit with request, validation, authorization/approval, departure, return, and result/event flow.

## Scope

This checkpoint establishes the leave domain contract:

- leave identity;
- detainee reference;
- purpose;
- request timestamp;
- verification state;
- lifecycle status;
- explicit commands for create, submit, review, approve, depart, return, receive, complete, reject, and cancel;
- mandatory reason for rejection/cancellation.

## State vocabulary

DRAFT → SUBMITTED → REVIEWED → APPROVED → DEPARTED → RETURNED → RECEIVED → COMPLETED

REJECTED and CANCELLED are terminal outcomes for the applicable workflow path.

This is a domain vocabulary contract, not an authorization implementation. Actual transitions must later enforce policy, role, duty, scope, state, segregation of duties, transaction/idempotency, and audit.

## Explicit non-scope

No:

- database migration;
- persistence;
- real detainee data;
- automatic approval;
- automatic departure/return;
- escort assignment;
- document generation;
- authorization bypass;
- AI/OCR/WhatsApp;
- production mutation.

Safety: synthetic-data-only, Migration Freeze TRUE, AI_ENABLED FALSE.
