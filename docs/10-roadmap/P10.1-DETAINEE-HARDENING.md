# P10.1 — DETAINEE DOMAIN HARDENING

Status: IMPLEMENTED / CONTRACT-VERIFIED / DATABASE-MAPPED

P10.1 hardens the detainee aggregate without changing the production schema.

## Domain invariants

- registration requires non-empty identity and verified provenance;
- provenance requires a capture timestamp;
- verified-by, when supplied, cannot be blank;
- detainee status transitions are explicit and deny-by-default;
- CLOSED is terminal;
- domain version is preserved in database metadata;
- scope identity is preserved through the mapping boundary.

## Runtime integration boundary

```
SCAN / INPUT
   ↓

   ↓
P10.1 DETAINEE INVARIANTS
   ↓
P9 AUTHORIZATION
   ↓
P9 TRANSACTION + IDEMPOTENCY
   ↓
mta_detainees
   ↓
AUDIT + OUTBOX
   ↓
OBSERVABILITY
```

The mapper is an infrastructure boundary. It does not bypass the P9 mutation transaction.

## Existing production table alignment

The current production `mta_detainees` schema is used as-is. Domain-only concepts that are not first-class columns are retained under `metadata` rather than triggering an uncontrolled migration.
