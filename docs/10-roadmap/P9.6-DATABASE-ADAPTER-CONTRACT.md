# P9.6 — Database Adapter & Database Contract

Status: contract implementation only.

## Source basis

The authoritative project work source establishes the next implementation order as:

P9.6 Database Adapter → P9.7 Transaction + Idempotency → P9.8 Outbox → P9.9 Private Storage → P9.10 Observability → P9.11 Test Harness → P9.12 CI → P9.13 Kernel Certification.

## Scope

P9.6 establishes the application-facing database boundary without performing a migration.

The adapter contract separates:

- environment;
- database role;
- connection lifecycle;
- parameterized query execution;
- healthcheck;
- shutdown.

Database roles are explicitly represented as:

- APP_RUNTIME
- MIGRATION
- READONLY

A production migration role is rejected by the contract unless the project later introduces an explicit change-management mechanism. This checkpoint does not implement that mechanism.

## Migration freeze

No schema migration is created or executed by P9.6.

This preserves the source requirement that migration remains frozen until the database/model/controls contract is approved.

## Security boundary

- no database credential is hard-coded;
- the adapter receives its connection string from configuration;
- query values are parameterized through the query contract;
- runtime and migration roles are distinct;
- synthetic data remains the repository boundary.

## Deliberate non-scope

P9.6 does not implement:

- PostgreSQL driver installation;
- schema migration;
- domain repositories;
- transaction orchestration;
- idempotency;
- outbox;
- storage;
- AI;
- production data access.

Those belong to later checkpoints or approved implementation gates.
