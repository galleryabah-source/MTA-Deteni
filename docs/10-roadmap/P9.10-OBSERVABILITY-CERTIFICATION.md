# P9.10 — OBSERVABILITY CERTIFICATION

Status: IMPLEMENTED / CONTRACT-VERIFIED / RUNTIME-WIRED

## Scope

P9.10 establishes a runtime observability boundary for the MTA DETENI kernel without introducing a new database schema or migration.

Required properties: structured application events; request ID and correlation ID continuity; duration/status/outcome capture; safe error sanitization; no authorization secrets, bearer tokens, API keys, passwords, or provider secrets in logs; health visibility remains separate from business data; observability failures must not silently mutate business state.

## Runtime contract

HTTP request -> requestId + correlationId -> authentication/authorization -> route handling -> response -> structured request.completed event.

Failures emit a stable public error code and a sanitized internal observability event.

The event may contain route, method, status, duration, role, resource, request ID and correlation ID, but never credentials or provider secrets.

## Evidence boundary

This certification does not claim external log-drain or browser HTTP E2E verification when the execution environment cannot reach the deployed endpoint. Such verification belongs to deployment/runtime verification.

P9.10 does not replace P9.5 audit. Audit remains immutable security evidence for material actions; observability is operational telemetry.
