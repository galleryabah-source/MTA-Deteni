# MTA DETENI — AI-Off Equivalence & Deterministic Report Continuity v1.0

## Status
**LOCKED ARCHITECTURAL REQUIREMENT — 25 September 2026**

MTA DETENI must not depend on an external AI API for operational continuity or for the existence of a valid report output.

> When AI is unavailable, rate-limited, disconnected, misconfigured, or exhausted, MTA DETENI must continue producing an output that follows the same approved template, field contract, ordering, pagination, validation and document lifecycle as the AI-assisted path.

The content may differ only where AI normally supplies optional interpretation or enrichment. It must never differ in governed template structure or authoritative source data.

## 1. Core Principle
Separate understanding from execution. AI may help understand and map information, but the final report is generated by deterministic contracts.

```text
FIELD EVIDENCE
     ↓
CANONICAL DATA / DAILY DATASET
     ↓
RULE ENGINE + VALIDATION
     ↓
APPROVED TEMPLATE
     ↓
DETERMINISTIC DOCUMENT ENGINE
     ↓
DOCX / PDF
```

AI is an optional accelerator. The renderer never waits for AI.

## 2. Three-Layer Equivalence Model
### Layer A — Structural Equivalence: mandatory
AI-ON and AI-OFF use the same template_id, template_version, page size/orientation, margins, header/footer, sections, tables, image slots, captions, numbering, pagination rules, document lifecycle, and integrity/hash mechanism.

### Layer B — Data Equivalence: mandatory for authoritative data
Authoritative values come from the same canonical dataset regardless of AI availability: date, shift/group, detainee identifiers, headcount, movement, temporary exit, escort, event time, photo references, and approved operational figures.

### Layer C — Enrichment Equivalence: best-effort
AI may improve narrative normalization, caption drafting, activity grouping, suggested classification, missing-field hints, and consistency suggestions. When AI is unavailable, deterministic rules and/or human input provide the fallback. The fallback must never invent facts.

## 3. Canonical Report Dataset
The system must not generate a report directly from raw evidence or directly from an AI response.

```text
Raw Evidence → Evidence Normalizer → Canonical Daily Dataset → Dataset Validation → Approved Dataset → Deterministic Renderer
```

The Canonical Daily Dataset is the contract between field operations and document generation.

## 4. AI ON / AI OFF Processing
### AI ON
Evidence → deterministic extraction → AI assistance → human verification → Canonical Daily Dataset → Template → Renderer

### AI OFF / 429 / timeout / network failure
Evidence → deterministic extraction → rule-based normalization → human verification → Canonical Daily Dataset → same Template → same Renderer

The two paths converge before rendering. The renderer does not know or care whether AI was available.

## 5. Deterministic Fallback Engine
| AI-assisted operation | AI-OFF mechanism |
|---|---|
| Activity classification | controlled event taxonomy + user selection |
| Date/time extraction | device/server timestamp + validated input |
| Number extraction | schema/type validation |
| Person/entity mapping | canonical IDs and explicit references |
| Photo grouping | event reference + capture sequence |
| Caption drafting | controlled caption templates |
| Narrative normalization | predefined sentence patterns + manual edit |
| Missing information detection | required-field rules |
| Consistency detection | cross-field validation |
| Report section mapping | explicit field-to-slot mapping |
| Pagination | deterministic pagination rules |
| Layout | approved template + renderer |
| Document integrity | deterministic hash |

An AI outage therefore affects assistance quality, not the report pipeline itself.

## 6. Caption and Narrative Strategy
Free-form AI prose must never be a hidden dependency. Laporan Harian should maintain governed patterns such as:

```text
[Kegiatan] dilaksanakan pada [waktu] di [lokasi] oleh [petugas/kelompok], dengan [jumlah] deteni.
```

The exact wording should be governed by the approved report template and operational SOP. AI may propose normalized narrative; human review may accept/edit it. Without AI, the same facts can be assembled using deterministic sentence templates. Raw note remains preserved as provenance.

## 7. Photo Strategy
Photos are first-class evidence. Every report image slot resolves through image_slot → evidence_id → verified photo → caption source → deterministic placement.

AI may suggest the best photo/slot, but the fallback uses explicit report inclusion flag, event reference, sequence, image-slot candidate, and verification status.

## 8. AI Gateway Contract
AI Gateway outcomes include SUCCESS, TIMEOUT, RATE_LIMITED, QUOTA_EXHAUSTED, UNAVAILABLE, INVALID_CREDENTIAL, MODEL_UNAVAILABLE, NETWORK_ERROR, and POLICY_BLOCKED.

These are operational metadata, not report data. The application must never convert an AI error into a failed report transaction. Use bounded timeout, bounded retry, failure classification, telemetry, and circuit breaking. No uncontrolled retry loop.

## 9. Cached / Previously Approved Intelligence
Previously approved artifacts may be reused where governance permits: approved template blueprint, field mappings, image-slot mappings, validation rules, caption patterns, normalized dictionaries, and controlled vocabularies.

These are governed application assets, not a reason to make the live AI API mandatory. They must be versioned and auditable and must never silently become stale authority.

## 10. Template Intelligence Without Live AI
After a reference document has been analyzed and approved once, operational generation must not require AI.

```text
REFERENCE DOCUMENT → AI analysis (optional authoring stage) → Human approval → ACTIVE TEMPLATE BLUEPRINT → VERSIONED REGISTRY → DETERMINISTIC GENERATION
```

A Laporan Harian template therefore remains usable when every AI provider is offline. A new reference document may use AI for efficient analysis, but it must have a governed manual/structured review path if AI is unavailable.

## 11. Quality Target
The target is contractual equivalence, not an impossible promise of identical AI-generated prose.

AI-ON and AI-OFF must be equivalent for template identity/version, structure, authoritative data, images, ordering, validation, lifecycle, audit/provenance, and integrity metadata.

For AI-derived enrichment, AI-ON provides suggested enrichment while AI-OFF provides deterministic enrichment or human input. Both become valid only after the same human verification boundary.

## 12. Report Generation State Machine
```text
CAPTURED → NORMALIZED → DATASET_READY → VALIDATED → REVIEW → APPROVED → GENERATED → INTEGRITY_VERIFIED → FINAL
```

AI assistance is an optional side path and never a required state. There must be no WAITING_FOR_AI state in the core report lifecycle.

## 13. Acceptance Tests
Mandatory synthetic tests: AI fully available; API disconnected; HTTP 429; quota exhausted; timeout; HTTP 5xx; DNS/network failure; invalid API key; all providers unavailable; AI Gateway unavailable; report generation while AI fails; repeated generation with AI OFF; deterministic regeneration; stable photo mapping; AI ON/OFF structural comparison; retry without duplicate transaction; no partial official document.

A release cannot pass if AI-OFF prevents a valid core report from being produced.

## 14. Operational Rule
> AI may improve the report; AI may never be required to produce the report.

> MTA DETENI must be able to produce the same governed report structure and authoritative content with AI OFF, even when the external API is disconnected, rate-limited, unavailable, or exhausted.

## 15. Governance Boundary
This document does not authorize production AI activation, external provider data transfer, database migration, schema change, or real detainee data in repository fixtures.

Implementation follows the existing contract → security → implementation → test → audit → controlled non-production → production gate sequence.
