# MTA DETENI — P13.2441–P13.2680 Roadmap

## Objective
Build the contract foundation for a single MTA DETENI application that can be hosted on a controlled local PC/server and accessed by tablets and smartphones over the same LAN, while retaining the same authorization, evidence, audit and governance boundaries.

## Checkpoints
- P13.2441–2480 — local server bootstrap and non-production runtime boundary.
- P13.2481–2520 — controlled LAN client discovery and trust boundary.
- P13.2521–2560 — durable synchronization journal with operation fingerprint.
- P13.2561–2600 — controlled backup rotation requiring verified restore evidence.
- P13.2601–2640 — continuity runtime gate combining server, clients, journal and backup controls.
- P13.2641–2680 — execution evidence and integration hardening remain pending until observable runtime telemetry is available.

## Target Architecture

`Internet/Cloudflare (when online) ↔ canonical application services ↔ Local PC/Server ↔ LAN ↔ Tablet/Smartphone`

The local runtime is not a fork of the application and is not an independent authority. It is a continuity deployment of the same application contracts.

## Non-Goals

- No production database.
- No schema migration.
- No real detainee data.
- No automatic internet failover that bypasses governance.
- No anonymous LAN clients.
- No autonomous AI decision-making.

## Gate

P13.2640 remains contract-ready only. Execution certification requires observable CI or local runtime evidence. The next work should harden actual packaging/startup configuration only after contract compatibility is audited.
