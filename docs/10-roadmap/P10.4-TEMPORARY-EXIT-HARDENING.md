# P10.4 — TEMPORARY EXIT / LEAVE HARDENING

Status: IMPLEMENTED / CONTRACT-VERIFIED / SCHEMA-PRESERVING

State machine:
REQUESTED → VALIDATED → APPROVED → DOCUMENTED → ESCORT_ASSIGNED → DEPARTED → RETURN_PENDING → RETURNED → COMPLETED

P10.4 binds the state machine to operational evidence without making the state machine itself the source of truth for detainee placement or movement.

## Invariants

- Detainee and actor/correlation identity are mandatory.
- Planned return must be after planned departure.
- Only legal state transitions are accepted.
- Detainee must be active.
- Active placement is required for operational leave processing.
- DOCUMENTED requires document evidence.
- ESCORT_ASSIGNED requires escort evidence.
- DEPARTED/RETURN_PENDING/RETURNED/COMPLETED require movement evidence.
- Optimistic versioning rejects stale state.
- Critical mutation remains behind P9 transaction/idempotency with audit and outbox.
- No production schema migration is introduced.

## Integration boundary

REQUESTED
  ↓
VALIDATED
  ↓
APPROVED
  ↓
DOCUMENTED → PRIVATE STORAGE / DOCUMENT EVIDENCE
  ↓
ESCORT_ASSIGNED → ESCORT AUTHORITY
  ↓
DEPARTED → MOVEMENT: TEMPORARY_EXIT_DEPARTURE
  ↓
RETURN_PENDING
  ↓
RETURNED → MOVEMENT: TEMPORARY_EXIT_RETURN
  ↓
COMPLETED → FINAL AUDIT / OUTBOX

The domain contract does not claim live database, HTTP, storage or dispatcher E2E.
