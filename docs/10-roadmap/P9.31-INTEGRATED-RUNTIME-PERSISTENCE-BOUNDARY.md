# P9.31 — Integrated Runtime Persistence Boundary

Status: CONTRACT / INFERRED

## Purpose

P9.31 composes the runtime adapter, transaction/idempotency bridge, mandatory audit boundary, and outbox boundary into one fail-closed readiness decision.

The contract does not perform database I/O. It is a precondition gate for the future concrete runtime implementation.

## Decision order

1. Runtime adapter available.
2. Transaction boundary available.
3. Mandatory audit evidence available.
4. Outbox available when the command policy requires it.
5. Only then: READY.

Any missing prerequisite returns an explicit BLOCKED result.

## Mutation envelope

Critical runtime mutations require:

- requestId
- correlationId
- idempotencyKey
- actorId
- policyVersion

Blank identity values are invalid.

## Safety boundary

This contract does not:

- open a database connection;
- execute SQL;
- create or alter schema;
- write production data;
- dispatch external messages;
- upload files;
- call AI providers.

It therefore preserves the current Migration Freeze and AI OFF controls while creating a single integration point for the next implementation stage.

The authoritative source explicitly identifies P9.2–P9.13 and states that persistence/runtime work must proceed through controlled contracts before production mutation. The P9.31 label is an implementation sequencing inference, not an authoritative checkpoint label.
