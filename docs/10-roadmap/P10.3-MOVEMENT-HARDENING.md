# P10.3 — MOVEMENT HARDENING

Status: IMPLEMENTED / CONTRACT-VERIFIED / SCHEMA-PRESERVING

## Scope

Movement is the event boundary between detainee state, placement, temporary exit and reporting.

## Hardened invariants

1. Movement identity requires event ID, detainee ID, actor ID and correlation ID.
2. TRANSFER requires distinct origin and destination placement references.
3. IN cannot declare an origin placement.
4. OUT cannot declare a destination placement.
5. TEMPORARY_EXIT_DEPARTURE cannot create a destination placement.
6. TEMPORARY_EXIT_RETURN cannot declare an origin placement.
7. A movement event cannot precede the latest known movement for the detainee.
8. Headcount reconciliation requires an explicit cutoff and remains authorization-protected.
9. Critical movement mutation must remain behind the P9 transaction/idempotency boundary, with audit and outbox.
10. No production schema migration is introduced.

## Architectural boundary

DETAINEE → PLACEMENT → MOVEMENT → TEMPORARY EXIT → HEADCOUNT / MONITORING → REPORTING

Movement is an event record, not a substitute for the authoritative placement state.
