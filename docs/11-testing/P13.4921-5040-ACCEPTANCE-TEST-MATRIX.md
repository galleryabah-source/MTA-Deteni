# MTA DETENI — P13.4921–5040 Acceptance Test Matrix

| Stage | Required observation | Evidence source | Certification rule |
|---|---|---|---|
| TEST_SUITE | typecheck + JS + TS regression | TEST / CI | exit success and captured output |
| RUNTIME | local non-production runtime health | LOCAL_EXECUTION | observable readiness |
| BROWSER | shell/navigation/smoke | LOCAL_EXECUTION | observable browser result |
| LAN | PC server + tablet + smartphone + reconnect | LOCAL_EXECUTION | each scenario observed and passed |
| REPORT | approved daily guard report rendering | LOCAL_EXECUTION | bindings + deterministic artifact + visual review |
| RECOVERY | backup/restore + integrity + replay + rebuild | LOCAL_EXECUTION | required recovery steps observed |
| SECURITY | security/regression review | TEST / CI / LOCAL_EXECUTION | review evidence explicitly recorded |

## Negative controls

- Missing observation → not certified.
- `NOT_RUN` → not certified.
- Failed control → not certified.
- Unexpected control ID → rejected.
- Production authorization → outside this acceptance matrix and remains blocked.

## Report fidelity

The matrix intentionally does not assign a visual-match PASS from source code alone. The supplied approved template must be rendered and visually reviewed in a controlled environment before that evidence can be certified.

## Local-first fidelity

The intended topology remains PC local server → LAN clients → offline-safe boundary → synchronized recovery. This matrix certifies behavior only when actually observed; it does not claim that the physical LAN or browser environment has already been tested.
