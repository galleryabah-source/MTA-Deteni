# MTA DETENI — P13.5761–5800 Report Rendering Evidence Gate

## Objective

Make actual DOCX/report rendering a concrete acceptance workstream rather than a source-level contract claim.

## Evidence identity

Each generated report artifact must record or be externally bound to:

- source template identity and hash;
- template version;
- renderer/library version;
- input snapshot identity;
- output artifact hash;
- page count;
- rendering timestamp;
- execution identity;
- visual review result.

## Fidelity checks

The controlled comparison must verify, at minimum:

- page size and orientation;
- margins and section geometry;
- header/footer placement;
- table structure and column widths;
- typography and paragraph hierarchy;
- labels and field order;
- page breaks;
- signature/approval areas;
- QR placement where applicable;
- absence of unexpected blank pages or clipped content.

## Acceptance

`GENERATED` is not equivalent to `ACCEPTED`.

The artifact becomes accepted only after deterministic generation succeeds and the visual review evidence is recorded against the approved source template.

## Safety

Use synthetic fixtures only. No production document, real detainee identity, or operational credential may be introduced into the repository or test artifacts.
