# P9.7 — Transaction + Idempotency Reconciliation

**Date:** 2026-09-23  
**Migration freeze:** ACTIVE

## Changes

1. Reconciled the transaction runner with the canonical P9.6 DatabaseAdapter contract.
2. Replaced the incompatible `adapter.query({text, values})` assumption with `adapter.execute({text, parameters})`.
3. Preserved BEGIN → work → COMMIT and BEGIN → work failure → ROLLBACK semantics.
4. Added regression coverage for the canonical adapter call shape.
5. Kept the idempotency store deterministic for ACQUIRED, IN_PROGRESS, REPLAY and CONFLICT states.

## Certification status

**P9.7 = NOT CERTIFIED / PARTIAL**

The code-level transaction semantics are aligned and testable, but production certification is intentionally blocked because the current idempotency implementation is an in-memory Map and the current Edge Function mutation path does not yet persist an idempotency record inside the same database transaction.

Therefore this work does **not** claim durable production idempotency.

## Required next boundary

Before P9.7 can become PASS:

- durable idempotency record must exist at the mutation boundary;
- request hash must be bound to the idempotency key;
- replay must return the original durable response;
- conflicting reuse must be rejected;
- transaction mutation and idempotency state must have atomic semantics;
- failure must not leave a falsely completed idempotency record.

No schema migration is introduced while the migration freeze is active.
